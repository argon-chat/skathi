The **Elements** tab is where you go when something looks wrong: a button sits 2px lower than its neighbour, a hover colour never shows, a panel is wider than you asked. The tree on the left is your app's live element tree; the styles on the right say why the selected element looks the way it does.

## Why is this button 2px off?

Start from the thing you can see. Press **⌖ inspect** (Ctrl+Shift+C) and click the button in the app. The click selects it instead of reaching your app, the tree opens down to it, and the app outlines it with its selector and size, such as `button.btn.primary · 103×32`. Esc cancels the pick.

The **rules** view lists every CSS rule that matched the element, the one that wins first, with:

- its selector, and the `@media` condition it sits in;
- its specificity and source order, the two numbers on the right (`2048·18`), which decide which rule wins;
- the state it applies in, such as `hover` or `active`; a rule that matched through an ancestor's state is shown as `group-hover`;
- its declarations, with the ones another rule overrides dimmed and struck through.

For the 2px: look for the `height`, `padding`, `border` or `margin` the two buttons do not share. A declaration the engine does not support carries its advisory under the rule, so a property Skathi ignores does not go unnoticed.

Each rule has a copy button that copies it as CSS.

## What did it end up with?

Rules say what was asked for; **computed** says what the element got. It lists the resolved values, grouped by state:

- **live** is what is in effect this frame;
- **base**, **hover**, **active**, **focus**, **focus-visible** and **focus-within** are what each state resolves to.

The values are the engine's own: sizes, edges and corners as the layout and paint code receive them. That makes this the place to check a value you computed with `calc()` or a variable, or to compare **live** with **hover** when a hover style does not show.

## Find an element without clicking it

Some elements are hard to click: hidden ones, zero-sized ones, ones under an overlay.

- **Search.** **find** (Ctrl+F) searches the whole tree. A row matches when its tag, class names, id or text contains what you typed: `primary` finds `button.btn.primary`, `reset` finds the button labelled Reset. Since 0.4 a query is also tried as a CSS selector, so `.btn.primary`, `#save` and `.toolbar > button` find what they select. Enter and Shift+Enter, or the arrows, step through the hits; each step selects the hit and expands its parents.
- **Breadcrumbs.** The bar under the tree lists the selected element's ancestors; click one to select it. It is the fastest way from a label to the flex container that positions it.
- **Vue fragment anchors.** The `<!---->` toggle shows the empty comment nodes Vue leaves for `v-if` and `v-for`. They paint nothing, so they are hidden by default; turn them on when you count children or debug a list that renders nothing.

Click a row to select it. The selected element is outlined in the app.

## What it does not do

The tree and the styles are read-only: the inspector does not edit attributes, text or CSS. To try a change, edit the file; `sk dev` applies a CSS or template edit in place, without a restart. To try a value without editing a file, set it from the [console](/devtools/console/): `document.querySelector(".btn").style.height = "34px"`.
