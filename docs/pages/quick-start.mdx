Go from a fresh directory to a native window using Bun and the Skathi CLI. Write the app in Vue 3 or Svelte 5: both run in the same host, with the same CSS, web APIs and window API. The code blocks on this page have a Vue and a Svelte tab, and the choice you make applies to every page.

## Before you begin

Skathi runs on Windows x64, macOS on Apple silicon and Linux x64. Its CLI needs [Bun](https://bun.sh/) 1.4 or later:

```powershell title="Windows" os="windows"
powershell -c "irm bun.sh/install.ps1 | iex"
```

```bash title="macOS and Linux" os="unix"
curl -fsSL https://bun.sh/install | bash
```

Open a new terminal afterwards so `bun` is on the `PATH`. If Bun is already installed, `bun upgrade` brings it up to date, and `bun --version` shows the version.

## Create an application

```bash
bun create skathi my-app
```

It asks for the app's name, a template, the platforms to package for, whether published builds keep devtools, and the package manager. `minimal` then asks for Vue or Svelte; every other template is written in one of them:

| Template   | Framework       | What it is                                                      |
| ---------- | --------------- | --------------------------------------------------------------- |
| `showcase` | Vue             | every SDK feature, one page each, with `vue-router` and `pinia` |
| `minimal`  | Vue or Svelte 5 | one window, one component                                       |
| `player`   | Svelte 5        | a music player dressed in shaders                               |
| `weather`  | Vue             | a weather app whose sky and rain are drawn by shaders           |
| `draw`     | Vue             | an infinite canvas for pens, drawn with WebGPU (since 0.5)      |

`player`, `weather` and `draw` are downloaded from [skathi-templates](https://github.com/argon-chat/skathi-templates). To skip the questions, pass them as options:

```bash
bun create skathi my-app --template minimal --yes
bun create skathi my-app --template minimal --framework svelte --yes
```

Then install the dependencies:

```bash
cd my-app
bun install
```

The app depends on `@skathi-native/cli`, so its `bun run` scripts and `bunx sk` use that version of `sk`. A Svelte app also depends on `svelte`, and its own `svelte/compiler` compiles the components, so keep it on version 5.

New in 0.4.0: the framework is the app's own dependency, and nothing of the other one is installed. A Vue app depends on `vue` 3.5, whose `vue/compiler-sfc` compiles its `.vue` files; the `showcase` template also depends on `vue-router` and `pinia`. A Svelte app has no Vue package at all. `tailwindcss` is installed only by an app that uses it.

An app created before 0.4.0 got `@vue/runtime-core`, `vue-router` and `pinia` from the runtime and `tailwindcss` from the CLI. Add what it uses:

```bash
bun add vue@^3.5           # a Vue app
bun add vue-router pinia   # if it imports them
bun add -d tailwindcss@3   # if it has a tailwind.config.*
```

A Svelte app's `tsconfig.json` now extends `@skathi-native/runtime/tsconfig.svelte.json`, which types the runtime without Vue. `sk dev`, `sk build`, `sk publish` and `sk check` stop with the command to run when a Vue app has no `vue`, or a `tailwind.config.*` has no `tailwindcss` 3 beside it.

## What is in the app

| File                            | What it does                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------------ |
| `src/main.ts`                   | the entry: mounts the root component                                                 |
| `src/App.vue`, `src/App.svelte` | the root component                                                                   |
| `assets/`                       | files packaged with the app; a relative `fetch("assets/hello.txt")` reads them       |
| `sk.config.json`                | name, platforms, the [`window` block](/window-api/config-window/), packaging options |
| `tsconfig.json`                 | type-checks against the runtime                                                      |

The entry mounts the root component. A Vue app calls `createApp(App).mount()` with no selector; a Svelte app calls `mount(App)` from `@skathi-native/runtime/svelte`. Both mount on the window's document root.

```ts title="src/main.ts (Vue)"
import { createApp } from "vue";
import App from "./App.vue";

createApp(App).mount();
```

```ts title="src/main.ts (Svelte)"
import { mount } from "@skathi-native/runtime/svelte";
import App from "./App.svelte";

mount(App);
```

## Open a native window

Start the development host:

```bash
bun run dev
```

Edit the root component and save to see it update; the window stays open. In Vue, a template edit re-renders in place and keeps the component's state. In Svelte, the edited component is hot-updated in place.

A component reads the window through `appWindow`. Its reads are reactive: in a Vue template or `computed`, and in Svelte markup, `$derived` or `$effect`. The button label below follows the window when you maximize it by double-clicking the title bar.

## Coming from Vue: what differs in Svelte

The template uses Svelte's DOM renderer. Svelte 5.59+ applications can opt into the experimental native renderer with `"svelte": { "renderer": "native" }` in `sk.config.json` (since 0.6). Form bindings, transitions and global event components need the DOM renderer. [Renderer comparison](/guides/svelte-support/#choose-a-renderer-since-06)

Skathi renders both frameworks into one element tree with the same renderer, so styling, layout, web APIs and the window API are the same. What differs is how the app plugs into Skathi:

- **Import from `@skathi-native/runtime/svelte`.** It exports `mount`, `unmount` and `SkWindow`, and importing it is what makes `appWindow` reads reactive in runes. The `app*` objects (`appWindow`, `appTray`, `appHotkeys`, `appStorage` and the rest) are the same in every framework: import them from `@skathi-native/runtime` or from `/svelte`, whichever you like.
- **Mount with `mount(App)`.** Pass `props` as in Svelte's own `mount`. The target defaults to the document root. A later `mount(Component, { target })`, for example into a pop-out window, is unmounted together with the app when the dev host reloads the app.
- **`<SkWindow>` takes callback props and bindings.** Events are `onopen`, `onclose`, `onfocus`, `onblur`, `onresize`, `onshow` and `onhide`. `bind:el`, `bind:windowId`, `bind:width`, `bind:height` and `bind:scale` read its values, and `bind:this` gives `mapFromMain()`. The [pop-out guide](/guides/pop-out-windows/) has both versions of every example.
- **There is no `<Teleport>`.** Put a pop-out's content in the `<SkWindow>` children, or `mount` a component into the element `bind:el` gives you.
- **Transitions are Svelte's.** Svelte runs `transition:`, `in:` and `out:` through `element.animate()`, which the host supports. Vue's `<Transition>` and `<TransitionGroup>` are part of the Vue entry only.
- **Type checking uses `svelte-check`** instead of `vue-tsc`, through `bun run typecheck`.

[Svelte support](/guides/svelte-support/) lists which Svelte features work in Skathi, and [Vue support](/guides/vue-support/) does the same for Vue.

Some parts are Vue-only:

- `createApp`, `<Teleport>`, `<Transition>`, `useCssModule()`, `useCssVars()` and the rest of the Vue API are exported from `@skathi-native/runtime` in an app that has `vue` installed. Without it, `@skathi-native/runtime` is the DOM layer and the `app*` objects only.
- The `showcase`, `weather` and `draw` templates use Vue. The showcase also uses the Vue libraries `vue-router` and `pinia`.
- Of the [performance advisories](/guides/performance-advisories/), the wasted re-render and long list advisories watch Vue component updates. In a Svelte app only the host-writes advisory is reported, with a total instead of component names.

## Check compatibility

Run the CLI checker when adding dependencies or porting browser-oriented code:

```bash
bun run check
```

It reports what in the app's code and its `node_modules` breaks or slows down under ahead-of-time compilation, and how well it is typed, for `.vue`, `.svelte` and `.ts` files alike. `bun run typecheck` runs `vue-tsc` or `svelte-check`.

Use the [CSS reference](/css/) and [web platform reference](/web-platform/) to check individual features. A familiar API name does not imply that every browser behavior is available.

## Build and package

Create a debug build with devtools, in `dist/debug`:

```bash
bun run build
```

Produce the release build, one executable to ship, in `dist/release`:

```bash
bun run publish
```

The release build has no devtools unless `"publishDevtools": true` is set in `sk.config.json`. Files such as `icu.skpk` ship beside the exe; since 0.6, `"publishSingleFile": true` puts them inside it. Run `bunx sk build --help` or `bunx sk publish --help` for packaging options.
