A settings panel, a filter sidebar, an export dialog: checkboxes, radio buttons, sliders, color swatches, drop-downs and file pickers are the parts of an app users reach for every day. In Skathi they are drawn natively by the renderer, styled after Chromium on Windows. A file input opens the operating system's file dialog; a color input opens a color picker Skathi draws. Each one works with `v-model` in Vue and `bind:value`, `bind:checked` or `bind:group` in Svelte, keyboard included.

[`accent-color`](/css/accent-color/) tints checkboxes, radios and sliders to match your brand, and [`appearance: none`](/css/appearance/) removes a control's default look when you want to draw your own. Text fields are on their own page: [`<input>` and `<textarea>`](/elements/text-fields/).

## A settings panel

Every control in one form, bound to one object. A form has no page to navigate to, so handle `submit` with `preventDefault()` (`@submit.prevent` in Vue) and save the data yourself.

```vue title="Settings.vue" framework="vue"
<script setup lang="ts">
import { reactive } from "vue";

const settings = reactive({
  notifications: true,
  theme: "system",
  fontSize: 14,
  accent: "#0090ff",
  language: "en",
});

function save() {
  localStorage.setItem("settings", JSON.stringify(settings));
}
</script>

<template>
  <form class="settings" :style="{ accentColor: settings.accent }" @submit.prevent="save">
    <label><input v-model="settings.notifications" type="checkbox" /> Notifications</label>
    <fieldset>
      <label><input v-model="settings.theme" type="radio" name="theme" value="light" /> Light</label>
      <label><input v-model="settings.theme" type="radio" name="theme" value="dark" /> Dark</label>
      <label><input v-model="settings.theme" type="radio" name="theme" value="system" /> System</label>
    </fieldset>
    <label
      >Size {{ settings.fontSize }}px <input v-model.number="settings.fontSize" type="range" min="12" max="20"
    /></label>
    <label>Accent <input v-model="settings.accent" type="color" /></label>
    <select v-model="settings.language">
      <option value="en">English</option>
      <option value="de">Deutsch</option>
      <option value="ja">日本語</option>
    </select>
    <button type="submit">Save</button>
  </form>
</template>

<style scoped>
.settings {
  display: flex;
  flex-direction: column;
  gap: 12px;
}
</style>
```

```svelte title="Settings.svelte" framework="svelte"
<script lang="ts">
  let settings = $state({
    notifications: true,
    theme: "system",
    fontSize: 14,
    accent: "#0090ff",
    language: "en",
  });

  function save(e: SubmitEvent) {
    e.preventDefault();
    localStorage.setItem("settings", JSON.stringify(settings));
  }
</script>

<form class="settings" style:accent-color={settings.accent} onsubmit={save}>
  <label><input bind:checked={settings.notifications} type="checkbox" /> Notifications</label>
  <fieldset>
    <label><input bind:group={settings.theme} type="radio" name="theme" value="light" /> Light</label>
    <label><input bind:group={settings.theme} type="radio" name="theme" value="dark" /> Dark</label>
    <label><input bind:group={settings.theme} type="radio" name="theme" value="system" /> System</label>
  </fieldset>
  <label>Size {settings.fontSize}px <input bind:value={settings.fontSize} type="range" min="12" max="20" /></label>
  <label>Accent <input bind:value={settings.accent} type="color" /></label>
  <select bind:value={settings.language}>
    <option value="en">English</option>
    <option value="de">Deutsch</option>
    <option value="ja">日本語</option>
  </select>
  <button type="submit">Save</button>
</form>

<style>
  .settings {
    display: flex;
    flex-direction: column;
    gap: 12px;
  }
</style>
```

- Clicking a `<label>` checks its checkbox or radio, and the arrow keys move through the radio group.
- The slider fires `input` while it moves, so the size label follows the thumb. `change` fires when a drag or a key press commits, if you only want the final value.
- The color swatch opens Skathi's color picker. Picking sets a lowercase `#rrggbb` and fires `input`, and `change` when the picker closes; Escape puts the old color back.
- The `<select>` list is drawn by Skathi, and typing a letter while it is closed jumps to the first matching option.
- Enter in a text field and the submit button both fire `submit`.

## Your own file button

The file input's own button copies Chromium's English strings, so most apps hide the input and open the dialog from a button of their own. `showPicker()` does that from the button's click. The dialog is the operating system's.

```vue title="AttachFiles.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const picker = ref<HTMLInputElement | null>(null);
const names = ref<string[]>([]);

function picked(e: Event) {
  const files = (e.target as HTMLInputElement).files;
  names.value = files ? Array.from(files, (f) => f.name) : [];
}
</script>

<template>
  <input ref="picker" type="file" accept="image/*" multiple hidden @change="picked" />
  <button @click="picker?.showPicker()">Attach images</button>
  <ul>
    <li v-for="n in names" :key="n">{{ n }}</li>
  </ul>
</template>
```

```svelte title="AttachFiles.svelte" framework="svelte"
<script lang="ts">
  let picker = $state<HTMLInputElement>();
  let names = $state<string[]>([]);

  function picked(e: Event) {
    const files = (e.target as HTMLInputElement).files;
    names = files ? Array.from(files, (f) => f.name) : [];
  }
</script>

<input bind:this={picker} type="file" accept="image/*" multiple hidden onchange={picked} />
<button onclick={() => picker?.showPicker()}>Attach images</button>
<ul>
  {#each names as n (n)}
    <li>{n}</li>
  {/each}
</ul>
```

The dialog needs a user gesture, so call `showPicker()` from a click, not from a timer or a mount hook. Dismissing the dialog, or choosing the same files again, fires `cancel` instead of `change`. To show a picked image, pass `URL.createObjectURL(file)` to an [`<img>`](/elements/img/).

## Things to watch for

- **No validation.** `required`, `min` and `max` are not checked, and a form's `submit` fires whatever the fields hold. Validate in the handler.
- **An uncancelled `submit` does nothing** but print an advisory. Always handle it.
- **`reset` does not restore values**, and `form.submit()` fires no event. Reset your state instead.
- **`<select multiple>` still drops down.** Each pick selects one option, with an advisory; a `v-model` bound to an array works.
- **There is no vertical slider.** The range track always runs along the width.

## Checkboxes and radios

`<input type="checkbox">` and `<input type="radio">` are native. A click, Space or a click on their `<label>` checks them. Radio buttons with the same `name` in the same form are a group, and the arrow keys move through it. They fire `click`, then `input` and `change`, and `preventDefault()` on the click undoes the change. `checked`, `defaultChecked`, `indeterminate` and `disabled` work, and so do `:checked`, `:indeterminate`, `:disabled` and `:focus-visible`.

## Range

`<input type="range">` is a native horizontal slider, 129 × 16 pixels unless CSS sizes it.

- `min`, `max` and `step`, including `step="any"`, apply.
- The arrow keys, Page Up, Page Down, Home and End move it, and so does dragging.
- `input` fires while it moves, `change` when a drag or a key press commits.
- `stepUp()` and `stepDown()` work.
- Style it with `::-webkit-slider-thumb` and `::-webkit-slider-runnable-track` (or the `-moz-range-` spellings), `accent-color`, and `appearance: none`.

## Color

`<input type="color">` is a swatch, 50 × 27 pixels by default. `::-webkit-color-swatch` and `::-webkit-color-swatch-wrapper` style it.

`value` is a lowercase `#rrggbb`. Any CSS color can be assigned, such as `#f05`, `rgb()`, `hsl()` or a name, and is converted to that form; anything that is not a color becomes `#000000`. Since 0.5 the `alpha`, `colorspace` and `hdr` attributes change that form, as described below.

### The picker (since 0.5)

A click, Enter or Space on the input opens a picker under it, drawn by Skathi on every platform. The picker is a popup window of its own, so it may extend past the app's window, as a browser's does. The app's window keeps the keyboard and stays active meanwhile.

- On Windows and X11 it opens above the input when there is no room below on the screen, and stays in the work area of the input's monitor.
- On macOS it does the same within the screen's visible area, clear of the menu bar and the Dock, and stays right above the app's window.
- On Wayland, where an app does not know where its window is, the compositor places it under the input, flips it above when there is no room, and slides it to stay on the output.
- If the popup window cannot be opened, the picker is drawn inside the app's window instead, opens above the input when there is no room below, and stays inside the window.

It follows the input's [`color-scheme`](/css/color-scheme/), light or dark, and the focused hex field takes the input's [`accent-color`](/css/accent-color/).

From the top it has:

- tabs for the shape of the color area: a saturation and brightness square with a hue slider, a hue wheel around a square, or a hue wheel around a triangle;
- an alpha slider when the input has the `alpha` attribute, and an intensity when it has `hdr`;
- a switch between hex, RGB, HSL, HSV and OKLCH, with a field per channel;
- up to eight recent colors.

The shape, the format and the recent colors are kept per app, in its storage folder. A recent color keeps its alpha and intensity; one with an intensity other than 0 has a dot in its corner.

- Dragging in the color area or a slider, typing in a field, or picking a recent color sets `value` and fires `input` at once.
- Enter, a click outside the picker, or the window losing focus closes it and fires `change` if the value changed. The click outside does nothing else. Moving or resizing the window closes it the same way.
- Escape closes it and puts back the value it opened with, with an `input` event if the value had changed. No `change` fires.

| Key                           | In the picker                                                                                                                       |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Tab, Shift+Tab                | Move between the shape tabs, the color area, the sliders, the format switch, the fields and the recent colors.                      |
| Arrow keys                    | In the square: saturation left and right, brightness up and down. On a slider: move it. Among the recent colors: pick the next one. |
| Arrow keys on tabs            | Pick the next shape or format. The ring of the wheel and the triangle is the hue slider.                                            |
| Shift+arrow keys              | Ten times the step.                                                                                                                 |
| Page Up, Page Down, Home, End | Large steps and the ends of a slider.                                                                                               |
| `0`–`9`, `a`–`f`, Backspace   | Edit the hex field. Three or six digits (four or eight with `alpha`) apply.                                                         |
| `0`–`9`, `.`, Up, Down        | Edit an RGB, HSL, HSV or OKLCH field. Each number applies as it is typed; Up and Down step it.                                      |
| Ctrl+A, Ctrl+C, Ctrl+V        | Select, copy and paste in a field. A pasted CSS color such as `rgb(…)` is converted.                                                |

The hex field shows the color as sRGB. The RGB fields are 0 to 255 in the input's color space, HSL, HSV and A are in degrees and percent, and OKLCH is lightness in percent, chroma and hue.

There is no eyedropper.

### Alpha (since 0.5)

With the `alpha` attribute the picker shows an alpha slider and the swatch shows transparency over a checkerboard. `value` then follows the HTML standard: `color(srgb r g b / a)`, with each channel rounded to 8 bits, such as `color(srgb 1 0.501961 0 / 0.5)`. An opaque color leaves out the `/ a`. Any CSS color can be assigned, `#ff800080` included. Put `alpha` before a static `value` in the markup, or bind the value with `v-model` or `bind:value`: a `value` set before the attribute is converted without its alpha.

### Display P3 (since 0.5)

`colorspace="display-p3"` keeps the color in Display P3, the wider gamut of most current displays, as the HTML standard specifies. `value` is `color(display-p3 r g b)`, with `/ a` under `alpha`, and its channels are not rounded to 8 bits. An assigned color in any space, `#ff0000` included, is converted: `#ff0000` becomes `color(display-p3 0.917488 0.200287 0.138561)`. The picker's square, wheel and fields work in P3 coordinates; its swatches are painted as the window shows them. `input.colorSpace` reads `"limited-srgb"` (the default) or `"display-p3"`.

```vue title="Brand.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const brand = ref("color(display-p3 0 0.6 1)");
</script>

<template>
  <input v-model="brand" type="color" colorspace="display-p3" />
</template>
```

```svelte title="Brand.svelte" framework="svelte"
<script lang="ts">
  let brand = $state("color(display-p3 0 0.6 1)");
</script>

<input bind:value={brand} type="color" colorspace="display-p3" />
```

### HDR colors (since 0.5)

The `hdr` attribute is Skathi's own. It adds an intensity to the picker: an exposure from −10 to +10 stops that multiplies the color by 2 to that power, with a slider, buttons for common stops and a preview of the color before and after. The preview glows when the result is brighter than white.

`value` stays a CSS color, in linear light with channels past 1: `color(srgb-linear 4 2 0.5)`, or `color(display-p3-linear …)` with `colorspace="display-p3"`, and `/ a` with `alpha`. Both work in a `style` binding, as below; `display-p3-linear` is not read in stylesheets. Reading a value back, the picker takes the intensity as the brightest channel's power of two, rounded, and the rest as the color: `color(srgb-linear 4 2 0.5)` opens at +2 stops.

```vue title="Glow.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const glow = ref("color(srgb-linear 4 2 0.5)");
</script>

<template>
  <input v-model="glow" type="color" hdr alpha />
  <div class="orb" :style="{ background: glow }" />
</template>
```

```svelte title="Glow.svelte" framework="svelte"
<script lang="ts">
  let glow = $state("color(srgb-linear 4 2 0.5)");
</script>

<input bind:value={glow} type="color" hdr alpha /><div class="orb" style:background={glow}></div>
```

Browsers ignore `hdr`, so the same markup in a web build gets a plain sRGB input.

### Show your own picker (since 0.5)

Before any picker opens, the input fires a `showpicker` event, which bubbles and can be cancelled. Call `preventDefault()` on it and nothing opens: show your own picker instead, and set `value` and dispatch `input` and `change` yourself when the user picks. One listener on a parent replaces the picker for every color input inside it.

```vue title="BrandColor.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";
import SwatchPopover from "./SwatchPopover.vue";

const color = ref("#0090ff");
const open = ref(false);
const input = ref<HTMLInputElement | null>(null);

function pick(next: string) {
  const el = input.value!;
  el.value = next;
  el.dispatchEvent(new Event("input", { bubbles: true }));
  el.dispatchEvent(new Event("change", { bubbles: true }));
  open.value = false;
}
</script>

<template>
  <input ref="input" v-model="color" type="color" @showpicker.prevent="open = true" />
  <SwatchPopover v-if="open" :value="color" @pick="pick" @close="open = false" />
</template>
```

```svelte title="BrandColor.svelte" framework="svelte"
<script lang="ts">
  import SwatchPopover from "./SwatchPopover.svelte";

  let color = $state("#0090ff");
  let open = $state(false);
  let input: HTMLInputElement;

  function pick(next: string) {
    input.value = next;
    input.dispatchEvent(new Event("input", { bubbles: true }));
    input.dispatchEvent(new Event("change", { bubbles: true }));
    open = false;
  }
</script>

<input
  bind:this={input}
  bind:value={color}
  type="color"
  onshowpicker={(e) => {
    e.preventDefault();
    open = true;
  }}
/>
{#if open}
  <SwatchPopover value={color} onpick={pick} onclose={() => (open = false)} />
{/if}
```

Dispatching `input` keeps `v-model` and `bind:value` in step, as with any input whose value you set from script.

To use the operating system's color dialog instead, set [`"colorPicker": "system"`](/sk-config/#colorPicker) in `sk.config.json`: `ChooseColor` on Windows, `NSColorPanel` on macOS, and zenity or kdialog on Linux. A pick there sets `value` and fires `input` and `change`; cancelling fires nothing. `showpicker` fires before it too. The OS dialog has no alpha, Display P3 or intensity: it ignores `alpha`, `colorspace` and `hdr`, and its sRGB pick is converted to the input's space.

### `showPicker()` (since 0.5)

`input.showPicker()` opens the picker from script, as a click would, and fires `showpicker` first. As in browsers, it needs a user gesture, such as your own button's click, and throws a `NotAllowedError` without one and an `InvalidStateError` on a disabled input. A click on the input without a gesture, such as `input.click()` from a timer, opens nothing and logs a warning.

```vue title="AccentButton.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const accent = ref("#0090ff");
const input = ref<HTMLInputElement | null>(null);
</script>

<template>
  <button @click="input!.showPicker()">Choose accent</button>
  <input ref="input" v-model="accent" type="color" style="display: none" />
</template>
```

```svelte title="AccentButton.svelte" framework="svelte"
<script lang="ts">
  let accent = $state("#0090ff");
  let input: HTMLInputElement;
</script>

<button onclick={() => input.showPicker()}>Choose accent</button>
<input bind:this={input} bind:value={accent} type="color" style="display: none" />
```

An input that paints nothing, as here, has the picker open at the pointer.

## Select

`<select>` draws a closed box like Chromium's on Windows: the selected option's label, a chevron, and the width of its widest option. `appearance: none` removes the chevron and the padding.

The list is drawn by Skathi, not as an OS menu. It opens under the box, or above it when there is no room, shows up to 20 rows before it scrolls, and closes when the window loses focus.

- The list (since 0.5) is a popup window of its own and may extend past the app's window. Moving or resizing the window closes it.
- On Windows, macOS and X11 the room it measures is the screen's, on the box's monitor (on macOS, clear of the menu bar and the Dock).
- On Wayland the compositor places it, flipping it above the box when there is no room below. It is not shortened to the room there, so the compositor may slide a long list over the box.
- If the popup window cannot be opened, the list opens inside the window and stays inside it.

The list's colors are a fixed light or dark palette; only the select's own solid background carries over.

- Alt+Up, Alt+Down, F4, Enter or Space opens the list.
- While it is closed, the arrow keys change the value, and typing selects the first option that starts with what was typed (the search restarts after a one-second pause).
- `<optgroup>` labels are bold and their options indented. Disabled and `hidden` options are honored.
- A pick fires `input`, then `change`.

`multiple` and `size` keep the drop-down: the box opens the list and each pick selects one option, with an advisory. The selection model behind it works, so `selectedOptions` and a `v-model` bound to an array do. `appearance: base-select` is not supported.

## File

`<input type="file">` opens the operating system's file dialog: `IFileOpenDialog` on Windows, `NSOpenPanel` on macOS, and the XDG desktop portal on Linux. `accept`, `multiple` and `webkitdirectory` are passed to it.

- A choice sets `files`, then fires `input` and `change`. Dismissing the dialog, or choosing the same files again, fires `cancel`.
- The dialog needs a user gesture. A `<label for>` pointing at the input opens it, and `showPicker()` opens it from your own button's click.
- `value` reads `C:\fakepath\` and the first file's name, as in browsers. Only `""` can be assigned.
- The button and its text copy Chromium's English strings. [`::file-selector-button`](/css/pseudo-file-selector-button/) styles the button.

[`<input type=file>` in the web-platform reference](/web-platform/input-type-file/) has examples, and [File System Access](/web-platform/file-system-access/) opens files and folders with handles you can write to.

## Labels

A `<label>` finds its control by `for`, or as its first labelable descendant. A click on it focuses a text field, or clicks the control: it checks a checkbox, opens a file dialog.

## Forms

A `<button type="submit">` and Enter in a text field fire the form's `submit` event; a reset button fires `reset`. `requestSubmit()` fires `submit` too. That is all a form does: there is no page to navigate to, so a `submit` you do not cancel only prints an advisory.

No constraint validation runs, and a reset does not restore the fields' values. `form.submit()` fires no event.

## Not implemented

`<progress>` and `<meter>` draw nothing, `<dialog>` has no `showModal()`, and `<details>` does not toggle. See [What is not here](/elements/overview/#what-is-not-here).
