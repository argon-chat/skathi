A designer animates a loading spinner, a success checkmark or an empty-state illustration in After Effects, exports it with Bodymovin, and hands you a `.json` file. `<lottie>` plays that file in your app as it is: put it in `assets/`, point `src` at it, and it animates. Telegram's `.tgs` stickers, which are the same JSON gzipped, play too.

There is no npm package to install and no player script to load. Skathi draws the element itself: the animation is parsed and rasterized by [ThorVG](https://www.thorvg.org/) on a thread of its own, and each finished frame is written straight into the element's GPU tile. The UI thread only moves the playhead, so a busy animation does not make your scrolling or typing slower, and a new frame costs a repaint, not a rebuild of the page. The attributes and events copy lottie-web's names, and the defaults copy `<lottie-player>`'s, so they will look familiar if you have used either.

For many small animated stickers on screen at once, such as reactions in a chat, use [`<sk-sticker>`](/elements/sk-sticker/), which shares decodes and frames between copies.

## Play and pause from a button

`autoplay` is not a one-time hint here: it is the play button. Bind it to state, and every change plays or pauses, holding the current frame. `loop` without a value loops forever.

```vue title="Spinner.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const playing = ref(true);
const loops = ref(0);
</script>

<template>
  <lottie class="hero" src="assets/hello.tgs" loop :autoplay="playing" @loopComplete="loops++" />
  <button @click="playing = !playing">{{ playing ? "Pause" : "Play" }}</button>
  <p>Played {{ loops }} times</p>
</template>

<style scoped>
.hero {
  width: 160px;
  height: 160px;
}
</style>
```

```svelte title="Spinner.svelte" framework="svelte"
<script lang="ts">
  let playing = $state(true);
  let loops = $state(0);
</script>

<lottie class="hero" src="assets/hello.tgs" loop autoplay={playing} onloopcomplete={() => loops++}></lottie>
<button onclick={() => (playing = !playing)}>{playing ? "Pause" : "Play"}</button>
<p>Played {loops} times</p>

<style>
  .hero {
    width: 160px;
    height: 160px;
  }
</style>
```

Vue compiles `<lottie>` as a custom element, so there is nothing to register. The element has no `play()` or `pause()` methods: state is the only control, which is what keeps it in step with your UI.

## Play on hover

An icon that comes alive under the pointer is the same binding, driven by `mouseenter` and `mouseleave`. Leaving pauses on the current frame; to snap back to the start, remount the element or show a still image instead.

```vue title="HoverIcon.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const hovered = ref(false);
</script>

<template>
  <button class="tool" @mouseenter="hovered = true" @mouseleave="hovered = false">
    <lottie class="icon" src="assets/icons/bell.json" loop :autoplay="hovered" />
    Notifications
  </button>
</template>

<style scoped>
.icon {
  width: 24px;
  height: 24px;
}
</style>
```

```svelte title="HoverIcon.svelte" framework="svelte"
<script lang="ts">
  let hovered = $state(false);
</script>

<button class="tool" onmouseenter={() => (hovered = true)} onmouseleave={() => (hovered = false)}>
  <lottie class="icon" src="assets/icons/bell.json" loop autoplay={hovered}></lottie>
  Notifications
</button>

<style>
  .icon {
    width: 24px;
    height: 24px;
  }
</style>
```

lottie-web's `hover` attribute is not supported; it prints an advisory that points at this pattern.

## Loop one part of the file

Designers often put an intro and an idle loop in one file. `segment` plays only a range of source frames, `loop` repeats it, and `mode="bounce"` runs it back and forth instead of jumping to the start, which suits a breathing or floating idle state:

```vue title="Mascot.vue" framework="vue"
<template>
  <lottie class="mascot" src="assets/mascot.json" segment="30,59" loop mode="bounce" autoplay />
</template>
```

```svelte title="Mascot.svelte" framework="svelte"
<lottie class="mascot" src="assets/mascot.json" segment="30,59" loop mode="bounce" autoplay></lottie>
```

`speed` scales the rate, and `direction="reverse"` plays backwards. A changed `segment` takes effect at once, keeping the playhead inside the new range.

## Scrub with a slider

With `autoplay` off, a segment of a single frame holds the animation on that frame. Bind it to a slider, a scroll position or a download's progress, and the animation follows the value instead of the clock:

```vue title="Scrubber.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const lastFrame = 119;
const frame = ref(0);
</script>

<template>
  <lottie class="hero" src="assets/onboarding.json" :segment="`${frame},${frame}`" />
  <input v-model.number="frame" type="range" min="0" :max="lastFrame" />
</template>
```

```svelte title="Scrubber.svelte" framework="svelte"
<script lang="ts">
  const lastFrame = 119;
  let frame = $state(0);
</script>

<lottie class="hero" src="assets/onboarding.json" segment="{frame},{frame}"></lottie>
<input bind:value={frame} type="range" min="0" max={lastFrame} />
```

Segment values are source frame numbers, not seconds or a 0 to 1 progress, and are clamped to the animation's range. Take that range from the file, the `ip` and `op` fields of the Lottie JSON, or from `totalTime`, which the events below report while it plays.

## Things to watch for

- **Frames, not seconds.** `currentTime` and `totalTime` on the events count source frames, as in lottie-web.
- **No `load` or `error` event.** A file that fails to load or parse prints a console warning, and the element stays empty. Check the console when nothing shows.
- **Size it in CSS.** An unsized `<lottie>` is 0 × 0 until the file loads, so the layout jumps when it does.
- **Reduced motion is yours to honor.** `<lottie>` does not read `prefers-reduced-motion`. Bind `autoplay` to `matchMedia("(prefers-reduced-motion: reduce)")` when the animation is decorative.
- **Off-screen animations keep their clock.** A hidden or scrolled-away element draws nothing, but its playhead advances and its events fire. Turn `autoplay` off when that matters.

## Attributes

| Attribute         | Values                                                                                    | Default             |
| ----------------- | ----------------------------------------------------------------------------------------- | ------------------- |
| `src`             | The animation's URL or path; see [Sources](#sources). Changing it reloads from the start. | none                |
| `autoplay`        | Boolean. Turning it on plays, turning it off pauses and holds the current frame.          | off                 |
| `loop`            | Absent: play once. Present or `"true"`: loop forever. A number `n`: play `n` more times.  | play once           |
| `speed`           | A multiplier on the animation's frame rate. Below 0 counts as 0, which stops it.          | `1`                 |
| `direction`       | `"-1"` or `"reverse"` plays backwards.                                                    | forwards            |
| `mode`            | `"bounce"` reverses at each end instead of jumping back to the start.                     | normal              |
| `segment`         | Two source frame numbers, `"30,59"` or `"30 59"`: play only that range.                   | the whole animation |
| `objectfit`       | `fill`, `contain`, `cover`, `scale-down` or `none`. The CSS `object-fit` property wins.   | `contain`           |
| `width`, `height` | Size hints in CSS pixels, unitless. CSS wins.                                             | none                |

A boolean attribute counts as on when present, unless its value is `"false"`, so `:autoplay="playing"` in Vue and `autoplay={playing}` in Svelte work as expected. `loop` counts the way lottie-web does: `loop="2"` plays three times. The only reflected property is `src`; there are no `currentTime` or `duration` properties.

These lottie-web and `<lottie-player>` attributes are not supported and print an advisory naming the alternative: `renderer`, `background` (use CSS `background`; the raster is transparent), `controls` (build controls in Vue or Svelte), `hover` (bind `autoplay` to pointer events), `intermission`, `count` (use `loop="n"`), `preserveAspectRatio` (use `object-fit`), `webworkers` and `subframe` (rendering is always off the UI thread and subframe).

## Events

| Event          | When                                                     | Carries                                                    |
| -------------- | -------------------------------------------------------- | ---------------------------------------------------------- |
| `enterFrame`   | every frame in which the playhead moved                  | `currentTime`, `totalTime`, `elapsed`, `progress` (0 to 1) |
| `loopComplete` | at each loop boundary, except the one that ends playback | `currentTime`, `totalTime`, `currentLoop`                  |
| `complete`     | playback finishes                                        | `currentTime`, `totalTime`, `loops`                        |

The values are on the event and on `detail`. `currentTime` is the fractional source frame and `totalTime` the animation's length in frames. The events do not bubble, and they are only dispatched to an element with a listener.

Vue turns `@loopComplete` into a listener for `loop-complete`, and Svelte's `onloopcomplete` listens for `loopcomplete`; both are accepted as `loopComplete`, and the same holds for `enterFrame`.

## Sources

`src` accepts:

- A path relative to the app, such as `assets/hello.tgs`, or a root-relative one. In a packaged app it is read from the package.
- `https:` and `http:` URLs, fetched through the same network stack as `fetch`, so they show in the devtools Network panel.
- `data:` URLs, base64 or percent-encoded, and `blob:` URLs.
- `file:` URLs and absolute paths.

The format is recognized by its first bytes, not its extension: gzip is read as `.tgs`, anything else as Lottie JSON. dotLottie (`.lottie`, a zip) is not supported.

### Packing

A packaged app carries only the files `sk build` packs. A file in the `assets/` directory is packed by default. Anywhere else, reference it so the build sees it:

- `<lottie src>` with a relative path such as `./hello.json`, in a Vue template, is compiled to an import, like `<img src>`. A `.json` file is imported as its URL, not as the parsed JSON.
- `new URL("./hello.tgs", import.meta.url)` in script packs the file and gives its URL.

A path that is not in the package fails with a warning that says so. Svelte templates do not get the template transform; use `new URL(…, import.meta.url)` there.

## How it is drawn

Each `<lottie>` loads and parses its own copy of the animation. File reads, parsing and drawing run on one dedicated `sk-lottie` thread; in-memory sources (`data:`, `blob:`, packaged files) are copied on the UI thread first. The renderer is ThorVG, with a pure-Rust fallback. ThorVG draws what it understands, including expressions, and skips the rest. Two Bodymovin idioms ThorVG does not draw are rewritten before parsing, and the rewrite is reported as an advisory.

The playhead lives on the UI thread. Each frame, it advances by the real time elapsed, times the animation's frame rate, times `speed`, and it is never snapped to whole frames. A pause longer than 250 ms counts as 250 ms. The element then asks the worker for that frame at the box's size in device pixels; one request per element is in flight, and a newer one replaces an older one.

A frame is drawn only while the element is visible: in a shown window and a visible page, and inside the viewport and every clipping ancestor. The playhead keeps advancing while it is hidden or scrolled away, and the events keep firing; an element removed from the document but kept alive, as in `<KeepAlive>`, keeps its clock too. When the element is removed, its animation, its ThorVG canvas and its GPU tile are released.

## Size and CSS

Before the animation loads the element has no natural size. After it loads, an unsized element takes the animation's width and height in CSS pixels, and an element with one side set takes the other from the animation's aspect ratio, or from CSS [`aspect-ratio`](/css/aspect-ratio/).

- [`object-fit`](/css/object-fit/) defaults to `contain`, not CSS's initial `fill`. The animation is rasterized at the contained size, so `cover` and `fill` scale that raster up.
- [`object-position`](/css/object-position/) applies.
- The raster is transparent, so the element's `background` shows through.

## Platforms

`<lottie>` behaves the same on Windows, macOS and Linux. It needs the host's `lottie` Cargo feature, on by default; without it the element is an empty box and the first one prints a warning. See [Features and size](/embedding/features/).

## Compared with lottie-web

- `autoplay` and `loop` are off by default.
- Playback is controlled by attributes only; there is no animation object with methods.
- A negative `speed` stops the animation instead of reversing it. Use `direction`.
- `loopComplete` does not fire on the boundary that ends playback.
- There are no `load`, `error`, `DOMLoaded` or `data_ready` events.
- Rendering is always raster: there is no SVG, canvas or HTML renderer to choose, and dotLottie files are not read.
