Search boxes, chat composers, rename fields, settings, notes: most apps are full of text fields, and users notice at once when one behaves oddly. In Skathi every `<input>` that is not a checkbox, radio, range, color or file input, and every `<textarea>`, is a native text editor written in Rust on gpui's text input. It lays out and draws the text, the caret and the selection itself, and takes keyboard and IME input from the operating system directly, so Japanese, Chinese and Korean input, undo, the clipboard and the platform's shortcuts work the way the user expects.

From your code it is the element you know: `v-model` and `bind:value` work as in a browser, and so do `input`, `keydown` and `focus`. The differences are few but worth knowing, and the recipes below work around the ones you are most likely to hit.

## A search box with Enter and Escape

A search field should take the keyboard when its view opens, search on Enter and clear on Escape. `autofocus` does nothing in Skathi, so focus the field once it is mounted. `keydown` runs before the editor acts on the key, so the handler sees Enter and Escape first.

```vue title="SearchBox.vue" framework="vue"
<script setup lang="ts">
import { onMounted, ref } from "vue";

const notes = ["Groceries", "Gym plan", "Gift ideas", "Travel checklist"];
const box = ref<HTMLInputElement | null>(null);
const query = ref("");
const results = ref<string[]>([]);

onMounted(() => box.value?.focus());

function onKey(e: KeyboardEvent) {
  if (e.key === "Enter") {
    const q = query.value.toLowerCase();
    results.value = notes.filter((n) => n.toLowerCase().includes(q));
  } else if (e.key === "Escape") {
    query.value = "";
    results.value = [];
  }
}
</script>

<template>
  <input ref="box" v-model="query" type="search" placeholder="Search notes" @keydown="onKey" />
  <ul>
    <li v-for="r in results" :key="r">{{ r }}</li>
  </ul>
</template>
```

```svelte title="SearchBox.svelte" framework="svelte"
<script lang="ts">
  const notes = ["Groceries", "Gym plan", "Gift ideas", "Travel checklist"];
  let box = $state<HTMLInputElement>();
  let query = $state("");
  let results = $state<string[]>([]);

  $effect(() => box?.focus());

  function onKey(e: KeyboardEvent) {
    if (e.key === "Enter") {
      const q = query.toLowerCase();
      results = notes.filter((n) => n.toLowerCase().includes(q));
    } else if (e.key === "Escape") {
      query = "";
      results = [];
    }
  }
</script>

<input bind:this={box} bind:value={query} type="search" placeholder="Search notes" onkeydown={onKey} />
<ul>
  {#each results as r (r)}
    <li>{r}</li>
  {/each}
</ul>
```

`type="search"` is a plain single-line field here: there is no clear button, so Escape is your user's way to clear it. Escape that your handler does not stop collapses the selection, and with no selection it goes on to the app, where a dialog's own Escape handler can close it.

## Save when the user is done

`change` never fires on a text field, and `v-model.lazy` updates on every keystroke with an advisory. For a field that saves only when the user has finished, such as renaming a file, keep a draft and commit it on `blur` and on Enter:

```vue title="RenameField.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const name = ref("Untitled");
const draft = ref(name.value);

function commit() {
  const value = draft.value.trim();
  if (value) name.value = value;
  else draft.value = name.value;
}
</script>

<template>
  <input v-model="draft" @blur="commit" @keydown.enter="commit" />
  <p>Saved as {{ name }}</p>
</template>
```

```svelte title="RenameField.svelte" framework="svelte"
<script lang="ts">
  let name = $state("Untitled");
  let draft = $state("Untitled");

  function commit() {
    const value = draft.trim();
    if (value) name = value;
    else draft = name;
  }
</script>

<input bind:value={draft} onblur={commit} onkeydown={(e) => e.key === "Enter" && commit()} /><p>Saved as {name}</p>
```

An empty name falls back to the last saved one. [Vue support](/guides/vue-support/) has more on `v-model` without `change`.

## A field that accepts only digits

No constraint validation runs, and `pattern` and `type="number"` do not filter what is typed; `maxlength` only caps the length. Clean the value in the `input` handler instead. This verification-code field keeps digits only, at most six, and enables the button when it is complete:

```vue title="CodeField.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const code = ref("");

function clean(e: Event) {
  const el = e.target as HTMLInputElement;
  const digits = el.value.replace(/\D/g, "").slice(0, 6);
  if (digits !== el.value) el.value = digits;
  code.value = digits;
}
</script>

<template>
  <input :value="code" placeholder="6-digit code" @input="clean" />
  <button :disabled="code.length !== 6">Verify</button>
</template>
```

```svelte title="CodeField.svelte" framework="svelte"
<script lang="ts">
  let code = $state("");

  function clean(e: Event) {
    const el = e.target as HTMLInputElement;
    const digits = el.value.replace(/\D/g, "").slice(0, 6);
    if (digits !== el.value) el.value = digits;
    code = digits;
  }
</script>

<input value={code} placeholder="6-digit code" oninput={clean} />
<button disabled={code.length !== 6}>Verify</button>
```

Setting `value` from script replaces the text and clears the undo history, which is why the handler writes only when something was removed. `beforeinput` is cancelable too, if you would rather refuse an edit than repair it.

## A chat composer

A message box sends on Enter, takes Shift+Enter as a new line, and puts an emoji where the caret is. Enter and Shift+Enter both insert a line break in a `<textarea>`, so the `keydown` handler tells them apart by `shiftKey`. `setRangeText()` replaces the selection and moves the caret past the new text:

```vue title="Composer.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const box = ref<HTMLTextAreaElement | null>(null);
const text = ref("");
const sent = ref<string[]>([]);

function onKey(e: KeyboardEvent) {
  if (e.key !== "Enter" || e.shiftKey || e.isComposing) return;
  e.preventDefault();
  if (text.value.trim()) sent.value.push(text.value);
  text.value = "";
}

function insert(emoji: string) {
  const el = box.value!;
  el.setRangeText(emoji, el.selectionStart, el.selectionEnd, "end");
  text.value = el.value;
  el.focus();
}
</script>

<template>
  <p v-for="(m, i) in sent" :key="i">{{ m }}</p>
  <textarea ref="box" v-model="text" rows="3" @keydown="onKey" />
  <button @click="insert('🙂')">🙂</button>
</template>
```

```svelte title="Composer.svelte" framework="svelte"
<script lang="ts">
  let box = $state<HTMLTextAreaElement>();
  let text = $state("");
  let sent = $state<string[]>([]);

  function onKey(e: KeyboardEvent) {
    if (e.key !== "Enter" || e.shiftKey || e.isComposing) return;
    e.preventDefault();
    if (text.trim()) sent.push(text);
    text = "";
  }

  function insert(emoji: string) {
    box!.setRangeText(emoji, box!.selectionStart, box!.selectionEnd, "end");
    text = box!.value;
    box!.focus();
  }
</script>

{#each sent as m, i (i)}
  <p>{m}</p>
{/each}
<textarea bind:this={box} bind:value={text} rows="3" onkeydown={onKey}></textarea>
<button onclick={() => insert("🙂")}>🙂</button>
```

`selectionStart` and `selectionEnd` count UTF-16 code units, like `String.prototype.length`, so an emoji outside the Basic Multilingual Plane counts as two. Inside `keydown` and `beforeinput` they give the selection the key is about to act on. `setRangeText()` does not fire `input`, which is why the handler copies the new value into the model, and like any assignment to `value` it clears the undo history.

## Things to watch for

- **No `change` event** on text fields. Use `blur` or Enter.
- **No `selectionchange` event** from a text field. Read `selectionStart` and `selectionEnd` when you need them, in `keydown`, `keyup`, `input` or `click`.
- **No context menu.** Right-click does nothing unless you handle `contextmenu` and draw a menu yourself.
- **Disabled fields stay focusable**, and their text can still be selected and copied.
- **A `disabled` `<fieldset>` does not disable the fields inside it.** Disable each one.

## No contenteditable

`<input>` and `<textarea>` are the only editable elements. [`contenteditable`](/web-platform/contenteditable/) is not supported: it makes an element focusable, but typing, pasting and IME input change nothing, and `document.execCommand()` does not exist. Editors built on it, such as CodeMirror, ProseMirror, Tiptap, Lexical, Quill and Slate, load but cannot be typed into.

For code or notes, use a `<textarea>`. For formatted text, edit the source, Markdown for example, in a `<textarea>` and render a preview beside it.

## Types

`text`, `search`, `url`, `tel`, `email`, `password` and `number` are all a single-line text field. `password` draws one bullet per character and refuses copy and cut; switching `type` between `password` and `text` shows and hides the value. `number` adds `valueAsNumber`, but there is no spinner and no input filtering.

`date`, `time` and the other types without a native control here are plain text fields too, without a picker. `hidden`, `submit`, `button`, `reset` and `image` are also drawn as text fields: use a `<button>`, and keep hidden values in state rather than in the tree.

A `<textarea>` is the same editor with several lines. Its initial value comes from its text content.

## Attributes

| Attribute              | Behavior                                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `value`                | The text. Setting it from script replaces the text and clears the undo history.                                                           |
| `placeholder`          | Shown while empty. In a single-line field, a line break in it shows as a space.                                                           |
| `disabled`, `readonly` | Both stop editing: no typing, paste, cut, undo or IME, and no caret. The field can still be focused, and text in it selected and copied.  |
| `rows`                 | A `<textarea>`'s minimum height in lines, 2 by default. CSS `height` wins.                                                                |
| `maxlength`            | The most UTF-16 code units the user can type, paste or commit from an IME; what does not fit is cut off. A value set from script is kept. |
| `tabindex`             | As on any element.                                                                                                                        |

`minlength`, `pattern`, `min`, `max`, `step` and `required` are reflected as properties but not enforced, and no constraint validation runs: there is no `checkValidity()` or `validity`, and a form's `submit` fires whatever the fields hold.

`autofocus` does nothing. `cols` and `wrap` are ignored: a textarea always wraps lines to its width. `spellcheck`, `autocorrect`, `autocapitalize`, `enterkeyhint` and `inputmode` are passed to the platform's text input, which ignores them on desktop: there is no spell-check underline.

## Keys

| Keys                                         | Action                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| Ctrl+Z / Cmd+Z                               | Undo                                                                     |
| Ctrl+Y, Ctrl+Shift+Z / Cmd+Shift+Z           | Redo                                                                     |
| Ctrl+C, Ctrl+X, Ctrl+V / Cmd+C, Cmd+X, Cmd+V | Copy, cut, paste                                                         |
| Ctrl+Insert, Shift+Delete, Shift+Insert      | Copy, cut, paste, on Windows and Linux                                   |
| Enter                                        | A new line in a `<textarea>`; in an `<input>`, fires the form's `submit` |
| Shift+Enter                                  | A new line in a `<textarea>`                                             |
| Up, Down in an `<input>`                     | Move to the start or the end                                             |
| Escape                                       | Collapses the selection; with none, the key goes on to the app           |
| Tab                                          | Moves focus; it is never typed                                           |
| Ctrl+Cmd+Space                               | The character palette, on macOS                                          |

Undo keeps 256 steps. Typing one character after another is one step, and so is a run of Backspace or a run of Delete; moving the caret starts a new step. Any other edit, a paste or a cut for example, is its own step, and a whole IME composition is one.

With the mouse, a double-click selects a word, a triple-click selects everything, Shift+click extends the selection, and a drag that leaves the field keeps selecting.

The field copies and pastes plain text. Pasting into a single-line field turns line breaks into spaces. A `copy` or `cut` handler that cancels the event can put other types on `clipboardData` with `setData()`, such as `application/x-my-format`; a `paste` in a Skathi app reads them back with `getData()`, while other apps get only the `text/plain`.

## IME

Composition input works on every platform, with the candidate window placed at the caret, also under CSS transforms:

| Platform | Through                                    |
| -------- | ------------------------------------------ |
| Windows  | IMM32                                      |
| macOS    | `NSTextInputClient`                        |
| Linux    | `zwp_text_input_v3` on Wayland, XIM on X11 |

`compositionstart`, `compositionupdate` and `compositionend` fire in Chromium's order. `v-model` waits for the composition to end before it updates the model. Setting `value` during a composition ends it and still fires `compositionend`.

## Events

| Event                                                     | Notes                                                                                |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `keydown`, `keyup`                                        | `keydown` runs before the editor acts on the key, and `preventDefault()` stops it.   |
| `beforeinput`                                             | Cancelable, except during a composition. Not fired for an edit that changes nothing. |
| `input`                                                   | With `inputType` and `data`.                                                         |
| `compositionstart`, `compositionupdate`, `compositionend` | See [IME](#ime).                                                                     |
| `copy`, `cut`, `paste`                                    | Fire first; `preventDefault()` cancels the action.                                   |
| `focus`, `blur`                                           |                                                                                      |
| `select`                                                  | After `select()`, `setSelectionRange()` and `setRangeText()`.                        |

`change` never fires on a text field.

## Styling

The field is styled like any box: `font`, `color`, `padding`, `border`, `background` and `text-align` apply.

- [`::placeholder`](/css/pseudo-placeholder/): its `color` applies; the default is the text color at 45 % opacity.
- [`::selection`](/css/pseudo-selection/): its `background` applies, its `color` does not.
- The caret is 2 pixels wide, blinks every 500 ms and has the text color. [`caret-color`](/css/caret-color/) is not supported.
- A single-line field scrolls sideways to keep the caret in view. A `<textarea>` scrolls with the wheel and draws its own thin scrollbar.
- [`field-sizing`](/css/field-sizing/) is not supported, and [`resize`](/css/resize/) shows no handle.

## Compared with the browser

- No `change` event on text fields.
- No `selectionchange` events from text fields, and no context menu.
- No constraint validation beyond `maxlength`.
- No spell checking, no `autofocus`, no date or time pickers, no number spinner.
- Disabled fields stay focusable.
- No `contenteditable`, so no rich text or code editor libraries.
