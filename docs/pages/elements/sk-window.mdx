A floating color palette, an inspector the user drags to a second monitor, a find bar, a tooltip that hangs outside the main window, a countdown drawn over the desktop: each is a second window. In Skathi you get one by wrapping part of your template in `SkWindow`.

There is no second app behind it, no message passing and no serialization. `SkWindow` is a component, imported from `@skathi-native/runtime` in Vue and `@skathi-native/runtime/svelte` in Svelte, not a custom element. It renders an ordinary `div`, and Skathi paints that `div` and everything inside it in a window of its own. The components inside keep running in the same app, on the same reactive state, so a click in the pop-out updates the main window in the same frame. It is also the only way to get a second window: `window.open()` returns `null`.

[Pop-out windows](/guides/pop-out-windows/) is the full guide: tooltips that follow the main window, click-through overlays, owned windows, focus, screen-capture protection, multiple monitors and the platform table. This page is the summary.

## A palette beside the main window

A palette edits what the main window shows. Leave `activate` off so it appears without taking the keyboard, and `:taskbar="false"` makes it an owned window on Windows: no taskbar button, and always above the main window.

## What it renders

`SkWindow` renders a `div.sk-window-root` that fills the window. Attributes and classes you put on `SkWindow` land on that root. Its children are its content.

Skathi runs one JavaScript realm, one app and one element tree. `SkWindow` marks its root node as popped out: the node stops painting in the main window, and a second window paints it and its subtree. Nothing is remounted. The components inside keep their instances, local state and watchers.

The window opens on the next effect cycle after the mount, not inside it. When it closes from outside your code, the subtree is painted inline in the main window again unless you unmount it, which is why the first example sets `notesOpen = false` in `@close`.

## Props, events and exposed values

The props set the window: `title`, `bounds`, `backdrop`, `alwaysOnTop`, `titleBarHeight`, `activate`, `visible`, `fullResolution`, `ignoreMouseEvents`, `contentProtection` and `monitor` apply live; `chrome`, `cover`, `taskbar`, `focusable`, `resizable`, `minWidth` and `minHeight` are read when the window is created. [Live and creation-time props](/guides/pop-out-windows/#live-and-creation-time-props) has the table, with defaults and platforms.

| Event    | Svelte callback | When                                                                                 |
| -------- | --------------- | ------------------------------------------------------------------------------------ |
| `open`   | `onopen`        | the OS window exists; carries its id, which devtools' `--window` takes               |
| `close`  | `onclose`       | the window closes: by the user or the OS, or because the component unmounts          |
| `focus`  | `onfocus`       | the window gains focus                                                               |
| `blur`   | `onblur`        | it loses focus                                                                       |
| `resize` | `onresize`      | its size or scale changes; carries `width`, `height` and `scale`                     |
| `show`   | `onshow`        | it is on screen with its first frame drawn: once after it opens, and after each hide |
| `hide`   | `onhide`        | it is hidden                                                                         |

The component exposes `el` (the root element, usable as a `<Teleport>` target), `windowId`, `width`, `height`, `scale` and `mapFromMain()`. In Svelte they are `bind:` targets, and `bind:this` gives `mapFromMain()`.

## CSS in a pop-out

CSS is evaluated against the window that paints the element: `@media` queries, `env(titlebar-area-*)` and `position: fixed` describe the pop-out. Global JavaScript APIs (`window.innerWidth`, `matchMedia()`, `appWindow`) describe the main window, even when the code runs from a click in a pop-out. [One app, many windows](/guides/pop-out-windows/#one-app-many-windows) has the full table.
