Some pictures are not made in JavaScript: a video player built on libmpv, a game engine's viewport, a CAD or map renderer, a camera feed, the output of another process. `<sk-surface>` puts them inside your page. The program that embeds Skathi presents frames to a surface by name, from whatever thread renders them, and every `<sk-surface>` with that `name` shows the newest one.

In the page it is an ordinary box. CSS sizes it, rounds its corners and moves it, an ancestor's `overflow` clips it, and your own controls sit over it. There is no second native window glued on top of the app, so nothing floats out of place when the user scrolls or a menu opens over the picture. A present never waits for the UI thread: the producer hands over a frame and goes on, and the element picks up the newest one on its next paint. On Windows and macOS the frame can be a GPU texture that is never copied through the CPU.

This page is the element, the part an app author writes. [Native frames](/embedding/native-frames/) is the producer side: the Rust `SurfaceHandle`, CPU and GPU frames, half floats, frame feedback and device loss.

## A player with your own controls

The usual layout is a positioned wrapper, the surface filling it, and the controls absolutely positioned over it. Until the producer's first frame arrives the element paints nothing over its own background, so a placeholder behind it covers the gap. `surfaceready` and `surfacelost` tell you when a frame is showing.

```vue title="Viewport.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const live = ref(false);
const size = ref("");

function resized(e: SkSurfaceEvent) {
  size.value = `${e.width} × ${e.height}`;
}
</script>

<template>
  <div class="player">
    <p v-if="!live" class="placeholder">Waiting for the renderer…</p>
    <sk-surface
      name="player"
      class="video"
      @surfaceresize="resized"
      @surfaceready="live = true"
      @surfacelost="live = false"
    />
    <div class="overlay">
      <span>{{ size }}</span>
    </div>
  </div>
</template>

<style scoped>
.player {
  position: relative;
  border-radius: 12px;
  overflow: hidden;
  background: #000;
}
.video {
  width: 100%;
  aspect-ratio: 16 / 9;
}
.placeholder,
.overlay {
  position: absolute;
  color: white;
}
.overlay {
  inset: auto 0 0 0;
  padding: 8px 12px;
}
</style>
```

```svelte title="Viewport.svelte" framework="svelte"
<script lang="ts">
  let live = $state(false);
  let size = $state("");
</script>

<div class="player">
  {#if !live}
    <p class="placeholder">Waiting for the renderer…</p>
  {/if}
  <sk-surface
    name="player"
    class="video"
    onsurfaceresize={(e) => (size = `${e.width} × ${e.height}`)}
    onsurfaceready={() => (live = true)}
    onsurfacelost={() => (live = false)}
  ></sk-surface>
  <div class="overlay">
    <span>{size}</span>
  </div>
</div>

<style>
  .player {
    position: relative;
    border-radius: 12px;
    overflow: hidden;
    background: #000;
  }
  .video {
    width: 100%;
    aspect-ratio: 16 / 9;
  }
  .placeholder,
  .overlay {
    position: absolute;
    color: white;
  }
  .overlay {
    inset: auto 0 0 0;
    padding: 8px 12px;
  }
</style>
```

- `surfaceresize` reports the painted size in physical pixels. The producer sees the same size from Rust, in `info()`, so it can render 1:1 with the screen without the app passing anything.
- Clicks on the surface go to the element and your listeners, never to the producer. Buttons that play, pause or seek call your program through a [native module](/embedding/native-modules/).
- Vue compiles every `sk-*` tag as a custom element, so there is nothing to register. In Vue the events are typed as the global `SkSurfaceEvent` and `SkSurfaceDisplayEvent`; in Svelte, `@skathi-native/runtime/svelte` types the element's `name` and its four events.

## One stream, two sizes

Any number of elements can name the same surface, and each shows the newest frame at its own size: a thumbnail strip and a main view, say. The producer still renders each frame once: the size it sees in `info()` is the largest visible element's.

```vue title="Monitor.vue" framework="vue"
<script setup lang="ts">
import { ref } from "vue";

const cameras = ["front", "back", "side"];
const selected = ref("front");
</script>

<template>
  <sk-surface class="main" :name="selected" />
  <div class="strip">
    <button v-for="cam in cameras" :key="cam" :class="{ on: cam === selected }" @click="selected = cam">
      <sk-surface class="thumb" :name="cam" />
    </button>
  </div>
</template>

<style scoped>
.main {
  width: 100%;
  aspect-ratio: 16 / 9;
}
.strip {
  display: flex;
  gap: 8px;
}
.thumb {
  width: 120px;
  height: 68px;
  pointer-events: none;
}
</style>
```

```svelte title="Monitor.svelte" framework="svelte"
<script lang="ts">
  const cameras = ["front", "back", "side"];
  let selected = $state("front");
</script>

<sk-surface class="main" name={selected}></sk-surface>
<div class="strip">
  {#each cameras as cam (cam)}
    <button class:on={cam === selected} onclick={() => (selected = cam)}>
      <sk-surface class="thumb" name={cam}></sk-surface>
    </button>
  {/each}
</div>

<style>
  .main {
    width: 100%;
    aspect-ratio: 16 / 9;
  }
  .strip {
    display: flex;
    gap: 8px;
  }
  .thumb {
    width: 120px;
    height: 68px;
    pointer-events: none;
  }
</style>
```

Changing `name` binds the element to the other surface at once. A CPU frame is uploaded once for each visible element that shows it, so many large copies of a CPU surface cost more than many copies of a GPU one.

## Things to watch for

- **Only visible elements take frames.** A frame presented while no element is visible is not uploaded; the newest one shows when an element becomes visible again. `display: none` counts as hidden, `opacity: 0` does not.
- **No `name` property.** From plain JavaScript use `setAttribute("name", …)`. Vue's `:name` and Svelte's `name={…}` set the attribute.
- **Children are not drawn.** Put overlays next to the element, positioned over it.
- **Linux shows CPU frames only**, and its windows stay SDR.

## Attributes

| Attribute         | What it does                                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| `name`            | The surface to show, trimmed. Changing it binds the element to the other surface. An empty name shows nothing. |
| `width`, `height` | Size hints in CSS pixels, unitless, as on `<img>`. CSS wins.                                                   |

That is all the element reads. The pixel format, the color space and the frames themselves are set from Rust.

## Events

| Event                  | When                                                                                                                              | Carries                                                                                               |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `surfaceresize`        | the painted size changes, and on first layout                                                                                     | `width`, `height` in physical pixels, `devicePixelRatio`                                              |
| `surfaceready`         | a frame shows for the first time, and again after a lost frame is replaced                                                        | `width`, `height` of that frame                                                                       |
| `surfacelost`          | the frame shown goes away                                                                                                         | `reason`: `"cleared"` or `"device"`                                                                   |
| `surfacedisplaychange` | the display is first known, its properties change, the window switches to or from HDR output, or the element moves to another one | `headroom`, `potentialHeadroom`, `refreshRate`, `sdrWhiteNits`, `hdr`, `outputHdr`, `variableRefresh` |

The values are on the event itself and on `detail`. The events do not bubble and cannot be cancelled, and they are only dispatched to an element that has a listener for them.

- `surfaceresize` reports the size in physical pixels: the CSS size times the window's scale, rounded. It fires while the element is in the document with a non-zero width, visible or not.
- `surfaceready` carries the frame's size, not the box's, and no `devicePixelRatio`.
- `surfacelost` fires only for an element that has shown a frame. `"cleared"` means the producer called `clear()`; `"device"` means the GPU device was lost and the frame with it. A CPU frame survives a device loss.
- `surfacedisplaychange` fires on Windows and macOS, on a change above 1 %. `refreshRate`, `sdrWhiteNits` and `variableRefresh` are `null` where the platform does not say. `outputHdr` is whether the element's window draws HDR now. [The display](/embedding/native-frames/#the-display) explains the values.

## Size and CSS

The box is 300 × 150 CSS pixels unless CSS or the `width` and `height` attributes size it. Size it as you would a `<video>`: a width and an `aspect-ratio`, or both sides.

The frame is scaled into the box:

- [`object-fit`](/css/object-fit/) defaults to `contain`, as on `<video>`; `cover`, `fill`, `none` and `scale-down` apply too.
- [`object-position`](/css/object-position/) places the frame in the box.
- [`image-rendering`](/css/image-rendering/) inherits. Its default, `auto`, uses bounded Catmull–Rom on magnified axes and bilinear sampling at native size or when shrinking. Use `image-rendering: pixelated` for nearest-neighbour sampling. In both modes the atlas tile keeps the producer's frame dimensions.
- [`border-radius`](/css/border-radius/) and an ancestor's `overflow` clip it.
- `transform`, `opacity` and `z-index` apply to the picture like to any other element, because the frame is drawn in the page, not in a window of its own.
- [`dynamic-range-limit`](/css/dynamic-range-limit/) caps how bright the element may get on an HDR display. The producer reads the result as its content headroom; see [HDR windows](/embedding/native-frames/#hdr-windows).

Until the first frame arrives the element paints nothing over its own background, so a `background` or a poster image set in CSS shows through. After `surfacelost` it paints nothing again.

## What counts as visible

The element takes a frame on its next paint, and only while it is visible: in the document, in a shown window, not in a hidden page, with a non-zero painted size, and with its painted rectangle inside the viewport and every clipping ancestor. `display: none` counts as hidden. `opacity: 0` and an element covered by another one count as visible. A GPU frame whose copy is still running when the element paints does not hold the picture back: the element shows the newest frame already copied, and the newer one on a later paint.

## Several elements, one surface

Each element that names a surface shows the same newest frame at its own size. The size the producer sees in `info()` is the largest visible element's. A CPU frame is uploaded once for each visible element that shows it.

## Input and focus

The element is an ordinary hit target. Clicks, pointer events and the wheel go to the element and to your listeners, as on a `<div>`; nothing is forwarded to the producer. `pointer-events: none` lets them through to what is under it. With a `tabindex` it takes focus.

## Platforms

| Platform | Frames the element can show                                                                   | `surfacedisplaychange` |
| -------- | --------------------------------------------------------------------------------------------- | ---------------------- |
| Windows  | CPU BGRA; Direct3D 11 and 12 textures; shared textures from another device, process or Vulkan | yes                    |
| macOS    | CPU BGRA; Metal textures, IOSurfaces, CVPixelBuffers                                          | yes                    |
| Linux    | CPU BGRA only                                                                                 | no                     |

On Windows and macOS a half-float surface on an HDR display switches the window to HDR output while it shows. Linux windows stay SDR.

## Compared with the browser

There is no browser element like it. The closest is a `<video>` whose frames come from your own code, or a `<canvas>` you draw into from another thread; unlike both, the producer is native code outside JavaScript, and a present never waits for the UI. For a video file the OS can play, [`<video>`](/elements/video/) needs no Rust at all.
