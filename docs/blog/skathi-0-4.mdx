## Native modules

An embedder used to talk to its app through `appHost.call`, with names in strings and every value through JSON. In 0.4 the program gives the app a **native module**. Mark an `impl` block `#[skathi::module]` and the types that cross `#[skathi::data]`, register it on the builder, and the app imports the methods from `native:<name>`.

```rust title="src/main.rs"
#[skathi::data]
#[derive(Clone)]
pub struct Note {
    pub id: u64,
    pub title: String,
}

#[derive(Default)]
pub struct Notes(std::sync::Mutex<Vec<Note>>);

#[skathi::module]
impl Notes {
    pub fn count(&self) -> u32 {
        self.0.lock().unwrap().len() as u32
    }

    #[task]
    pub fn search(&self, text: String) -> Vec<Note> {
        let notes = self.0.lock().unwrap();
        let found = notes.iter().filter(|n| n.title.contains(&text));
        found.cloned().collect()
    }
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let ui = skathi::Builder::new()
        .payload_file("app/dist/release/.sk/app.skpk")
        .module("notes", Notes::default())
        .spawn()?;
    ui.wait();
    Ok(())
}
```

```vue title="app/src/NoteSearch.vue"
<script setup lang="ts">
import { ref, watch } from "vue";
import { count, search, type Note } from "native:notes";

const total = count();
const query = ref("");
const found = ref<Note[]>([]);

watch(query, async (text) => {
  found.value = await search(text);
});
</script>

<template>
  <input v-model="query" placeholder="Search notes" />
  <p>{{ found.length }} of {{ total }}</p>
  <p v-for="note in found" :key="note.id">{{ note.title }}</p>
</template>
```

Three kinds of export, one rule each:

- A `pub fn` taking `&self` runs inside the call, on the UI thread, and returns its value.
- The same with `#[task]` runs on a worker thread and returns a promise.
- `events(name = Type)` on the attribute declares what `Handle::emit_to` sends from any thread; the app's `on` receives it.

`bunx sk types --exe <your exe>` asks the exe for its modules and writes the app's `.d.ts`, so a renamed field fails the type check instead of a user. Under `sk dev`, or as its own exe, the import still resolves: `available` is `false` and each function throws an error that says the app is not embedded. The [native modules guide](/embedding/native-modules/) walks through a first module.

### No JSON in between

Arguments are read straight from the engine's values, and results are built into engine objects in one call. A `#[skathi::data]` struct converts field by field, with its field names made into engine strings once. A `&str` or a `&[u8]` is read in place for the length of a synchronous call.

## Native frames, now in HDR

`<sk-surface name="player">` shows what native code draws: a video player built on libmpv, a game engine's viewport, a renderer in another process. It is an ordinary element. `object-fit`, `border-radius`, clipping, transforms, opacity and z-order apply, and the app's Vue or Svelte controls sit on top of it.

Your program presents frames by name, from the thread that renders. A present stores the frame and returns: nothing waits for the UI, and a frame no one can see costs no upload. On Windows and macOS a frame never leaves the GPU.

| Platform   | Frames                                                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Windows    | Direct3D 11 textures; Direct3D 12 resources with a fence; shared handles from another device or process; Vulkan through a shared texture |
| macOS      | Metal textures; IOSurfaces; CVPixelBuffers from VideoToolbox, AVFoundation or ScreenCaptureKit, BGRA or 4:2:0                            |
| Everywhere | CPU frames in BGRA or BGRX; on Linux, CPU frames only                                                                                    |

### Half floats, and HDR output

A producer that renders in linear light can hand over half floats. Set the surface's format once, before presenting:

```rust
use skathi::SurfaceFormat;

let surface = skathi::surface("player");
surface.set_format(SurfaceFormat::Rgba16Float);
```

The values are linear extended sRGB, what Windows calls scRGB: 1.0 is SDR white, and highlights go above it. Every path takes them: `present_rgba16f` from the CPU, `R16G16B16A16_FLOAT` textures and shared handles on Direct3D, `RGBA16Float` on Metal, `'RGhA'` IOSurfaces and CVPixelBuffers.

On an SDR display each frame maps into the window's 8-bit sRGB with the exact sRGB curve, so SDR content looks the same as on the 8-bit path. Skathi's tests put all 256 sRGB code values through half floats and get every one back unchanged, on Direct3D 11, Direct3D 12 and Metal.

On an HDR display the window switches to HDR output while it shows a half-float surface that may be brighter than SDR white. Windows gets a half-float swap chain in scRGB, on Direct3D 12 and Direct3D 11; macOS gets an `RGBA16Float` layer with extended dynamic range. Two seconds after the last such element is gone, the window switches back. The rest of the page looks as it did: in the renderer's tests every pixel of the HDR page is within one 8-bit code value of the standard one.

A window that shows no HDR content never switches. It keeps the standard path, bit for bit, and skips the HDR swap chain, which takes about three times the memory.

CSS sets how bright each element may get, and the producer reads the result as `content_headroom()`, the peak to tone-map to:

```css title="player.css"
.thumbnail sk-surface {
  dynamic-range-limit: standard;
}
.player sk-surface {
  dynamic-range-limit: no-limit;
}
```

### The display, and every frame's fate

Each element showing a surface fires `surfacedisplaychange` with its screen's `headroom`, `potentialHeadroom`, `sdrWhiteNits`, `hdr`, `refreshRate` and `variableRefresh`. The producer reads the same from `info().display`, with the last vblank and the refresh period.

`on_frame` reports exactly one event per presented frame, in order: `Presented` with the refresh it first showed on, or `Dropped` as `Superseded`, `Hidden`, `DeviceLost` or `Closed`. Callbacks run off the UI thread, and an idle window costs nothing. In Skathi's surface example, a 24 fps clip on a 165 Hz screen shows each frame `Presented` and held for 7, 7, 7, 7, 7, 7, 7 and 6 refreshes, which is the cadence a player keeps its clock against.

[Native frames](/embedding/native-frames/) covers the API, [GPU frames on Windows](/embedding/gpu-frames/) and [on macOS](/embedding/gpu-frames-macos/) the producers.

## Surround and spatial audio

Web Audio graphs are multichannel now and follow the spec's channel rules: `channelCount`, `channelCountMode` and `channelInterpretation` on every node, speaker up- and down-mixing for mono, stereo, quad and 5.1, discrete mixing otherwise, up to 32 channels. `destination.maxChannelCount` is the output device's channel count. Raise `destination.channelCount` to it, and a 5.1 or 7.1 graph plays on a 5.1 or 7.1 device as such.

```ts title="intro.ts"
const audio = new AudioContext();
const track = await audio.decodeAudioData(await (await fetch("assets/sounds/intro-5.1.flac")).arrayBuffer());
// 6 on a 5.1 device; a stereo device keeps 2 and the track is mixed down.
audio.destination.channelCount = Math.min(track.numberOfChannels, audio.destination.maxChannelCount);
const source = audio.createBufferSource();
source.buffer = track;
source.connect(audio.destination);
source.start();
```

### Spatial audio on Windows

Set a panner's `panningModel` to `"spatial"` and Skathi hands it to the system's spatial sound renderer, Windows Sonic, Dolby Atmos or DTS, as a dynamic audio object. The renderer gets the signal before panning, its position relative to the listener and its distance and cone gain, and does the 3D rendering itself. The rest of the graph plays in the renderer's static bed, up to 7.1.4. Dolby Atmos for Headphones ignores the position of dynamic objects, so there Skathi pans each `"spatial"` panner across the 7.1.4 bed itself, which Atmos does render in 3D. `audioContext.spatialAudio` says what happened:

<Sample src="blog/SpatialPing" focus="panner,status" />

The showcase template's Audio page has a new Spatial card: a top-down 7.1.4 room where you drag a source around the listener and up over their head, snap it to any speaker, set it orbiting, switch between `spatial`, `HRTF` and `equalpower` to compare, and run a speaker test over the bed channels.

The renderer lives in a new crate, `sk-audio`, behind the `spatial-audio` Cargo feature of `skathi`. It is on by default and costs about 0.1 MB.

<Aside kind="warning" title="Windows only, with a fallback">

Without a spatial sound format on the device (Sound settings › Spatial sound), on macOS and Linux, and when the renderer fails, `"spatial"` panners render with HRTF, and `spatialAudio.reason` says why. The renderer's objects are limited, often 15 to 32 and shared with other apps; panners past the limit render with HRTF too.

</Aside>

## CSS for layout

Everything in this section is new in 0.4. Each feature has its page, with its limits, in the [CSS reference](/css/).

- **Container queries.** [`container-type`](/css/container-type/), [`container-name`](/css/container-name/) and the [`container`](/css/container/) shorthand; [`@container`](/css/at-container/) with `width`, `height`, `inline-size`, `block-size`, `aspect-ratio` and `orientation`, range syntax and `and`, `or`, `not`; style queries on custom properties; and the [`cqw`, `cqh`, `cqi`, `cqb`, `cqmin` and `cqmax` units](/css/unit-container/). A query Skathi cannot answer, such as `scroll-state()`, drops its block, and `sk check` reports it as `SK4004`.
- **Scroll snapping.** [`scroll-snap-type`](/css/scroll-snap-type/), [`scroll-snap-align`](/css/scroll-snap-align/), [`scroll-snap-stop`](/css/scroll-snap-stop/), [`scroll-padding`](/css/scroll-padding/) and [`scroll-margin`](/css/scroll-margin/), on every way a box scrolls: wheel, touchpad and touch, the scrollbar, `scrollTo()`, `scrollIntoView()` and the keyboard.
- **Keyboard scrolling.** Arrows, Page Up, Page Down, Space, Home and End scroll the focused element's nearest scroll container, after the app's key handlers, gliding unless reduced motion is on.
- **[`calc-size()`](/css/function-calc-size/) and [`interpolate-size`](/css/interpolate-size/).** `height: auto` transitions, and `calc-size(auto, size * 0.4)` is 40 % of the content's height.
- **[`@function`](/css/at-function/).** Custom functions with typed parameters and defaults. A [`--name(…)` call](/css/dashed-function/) is substituted like [`var()`](/css/function-var/).
- **[`light-dark()`](/css/function-light-dark/) and [`color-scheme`](/css/color-scheme/).** They resolve per element and follow `appWindow.theme` and the OS theme live. Checkboxes, radios, range, colour and file inputs and the select popup draw dark under a dark scheme.
- **The smaller ones.** [`flex-flow`](/css/flex-flow/); [`aspect-ratio`](/css/aspect-ratio/) `auto` and `auto <ratio>`; [`inline-size`](/css/inline-size/), [`block-size`](/css/block-size/) and their `min-` and `max-` forms; the [cursors](/css/cursor/) `all-scroll`, `cell`, `no-drop`, `zoom-out` and `none`; [`contain`](/css/contain/) `size`, `inline-size` and `strict`; and the media features [`prefers-reduced-transparency`](/css/media-prefers-reduced-transparency/), [`device-width`](/css/media-device-width/) and [`device-height`](/css/media-device-height/).

```css title="styles.css"
.profile {
  container: profile / inline-size;
}
@container profile (width >= 420px) {
  .profile .card {
    display: grid;
    grid-template-columns: 96px 1fr;
  }
}
.card h2 {
  font-size: clamp(16px, 6cqi, 28px);
}

.carousel {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
}
.slide {
  flex: 0 0 80%;
  scroll-snap-align: center;
}

.excerpt {
  height: calc-size(auto, size * 0.4);
  overflow: hidden;
  transition: height 300ms ease;
}
.excerpt.open {
  height: auto;
}
```

The showcase template has a new Layout page with these at work: a profile card that relayouts by its own width, sticky letter headers in a scrolling list, a snapping carousel with a `scroll-snap-stop` toggle, and `aspect-ratio` transitions.

## CSS for shape and light

**[`corner-shape`](/css/corner-shape/) and `superellipse()`.** `round`, `squircle`, `bevel`, `scoop`, `notch`, `square` and `superellipse()`, as a shorthand of one to four values, with the physical, logical and per-side longhands. The shapes interpolate in transitions, `@keyframes` and `element.animate()`. The background, borders, outline, `box-shadow`, `backdrop-filter`, `--shading`, `overflow` and `clip-path` clips and hit testing all follow the shape, and an `<img>` or `<video>` clips its picture to it.

```css title="tag.css"
.tag {
  padding: 4px 12px;
  border-radius: 8px;
  corner-shape: bevel;
  background: #2563eb;
  transition: corner-shape 200ms ease;
}
.tag:hover {
  corner-shape: squircle;
}
```

**[`dynamic-range-limit`](/css/dynamic-range-limit/)**, with `standard`, `constrained` and `no-limit`, and [`dynamic-range-limit-mix()`](/css/function-dynamic-range-limit-mix/), cap how bright an element's HDR content gets, as in the [surface section](#native-frames-now-in-hdr). The media features [`dynamic-range`](/css/media-dynamic-range/) and [`video-dynamic-range`](/css/media-video-dynamic-range/) match `high` while the window's display is in HDR and the window can draw it.

<Aside kind="new" title="Already there before 0.4">

[Masks](/css/mask/), [`text-shadow`](/css/text-shadow/), the colour functions ([`hwb()`](/css/function-hwb/), [`lab()`](/css/function-lab/), [`lch()`](/css/function-lch/), [`oklab()`](/css/function-oklab/), [`oklch()`](/css/function-oklch/), [`color()`](/css/function-color/), [`color-mix()`](/css/function-color-mix/) and relative colours) and [view transitions](/css/feature-view-transitions/) have been in Skathi since 0.2, and [`position: sticky`](/css/position/) since 0.3. The showcase's Styles page now puts them next to the new features: `corner-shape` swatches, `text-shadow`, `hsl()` against `oklch()` ramps, `color-mix()`, `display-p3` and relative colours, a `light-dark()` panel and an `@function` palette.

</Aside>

## Forms and motion in Vue and Svelte

- **Checkboxes and radios are native controls.** They used to render as text fields. A click, Space or a label toggles them, radios group by name and move with the arrow keys, and they draw in [`accent-color`](/css/accent-color/) or drop their look under [`appearance: none`](/css/appearance/). Vue's `v-model` on checkboxes (a boolean, an array, a `Set`, `true-value` and `false-value`) and radios works, and so do Svelte's `bind:checked`, `bind:indeterminate` and `bind:group`.

<Sample src="blog/Export" focus="checks,radios" />

- **[`:checked`](/css/pseudo-checked/) follows the selected `<option>`**, so Svelte's `bind:value` on a `<select>` works, single and multiple.
- **`<Transition>` waits for CSS animations** as well as transitions. `<TransitionGroup>` plays its moves with the `-move` class, and Svelte's `animate:flip` works.
- **Errors go where Vue sends them.** What a template handler throws reaches `app.config.errorHandler` and `onErrorCaptured`. A throwing listener is reported as uncaught, as in a browser, and the other listeners still run.

[Vue support](/guides/vue-support/) and [Svelte support](/guides/svelte-support/) are new pages that list what works, what has limits and what does not, each with its `sk check` code.

## The main window

The main window opens where `sk.config.json` says, on the monitor it names, with no flash at a default spot first:

```json title="sk.config.json"
{
  "window": {
    "width": 420,
    "height": 640,
    "x": 24,
    "y": 24,
    "monitor": "cursor"
  }
}
```

- `x` and `y` are CSS px from the top-left corner of the monitor's work area, the part the taskbar or Dock leaves free. An axis without a value is centred.
- `monitor` is `"primary"`, the default, `"cursor"` for the monitor under the pointer, or an index from `0`.
- The window is kept inside the work area, and shrunk to fit it.

Two window fixes: moving or resizing the main window in the same turn a pop-out closes is no longer lost, and `window.y` and `<SkWindow>` bounds land exactly, where they were 4 px high at 100 %.

## Packaging and crates

- **Frameworks are your app's dependencies.** `@skathi-native/runtime` no longer depends on Vue, pinia or vue-router; `vue` ^3.5 and `svelte` ^5.57.3 are optional peers. The CLI compiles `.vue` files with the app's own `vue/compiler-sfc`, and loads `tailwindcss` ^3.4, an optional peer, only when a `tailwind.config.*` exists. A Svelte app installs nothing of Vue. This one needs a change; see [Breaking changes](#breaking-changes).
- **Crates released on their own.** `skathi-gpui` and `redjs` now release from their own repositories, on version lines of their own, as `skathi-taffy` already did. A Skathi release publishes only Skathi's crates and requires versions of the three that crates.io already has.
- **Smaller embedders.** `lottie`, `video`, `hotkeys`, `webview` and `spatial-audio` are new Cargo features of `skathi`, all on by default. Turned off, their crates leave the build, and the app gets a truthful answer: `<video>` is an empty box that warns once. A minimal embedder is 101.5 MB with every default feature, 84.9 MB with only `prod`, and 74.0 MB with `icu-root` and `no-devtools` added. [Features and size](/embedding/features/) lists each feature's cost.

## Breaking changes

<Change title="Vue, Svelte and Tailwind are your app's own dependencies" who="Every app">

An app created before 0.4 got Vue's runtime, vue-router and pinia from `@skathi-native/runtime`, and `tailwindcss` from the CLI. Add what it uses:

```bash
bun add vue@^3.5           # a Vue app
bun add vue-router pinia   # if it imports them
bun add -d tailwindcss@3   # if it has a tailwind.config.*
```

`sk dev`, `sk build`, `sk publish` and `sk check` stop with the command to run when a Vue app has no `vue`, or a `tailwind.config.*` has no `tailwindcss` 3 beside it.

</Change>
<Change title="Svelte apps extend the Svelte tsconfig" who="Svelte apps">

A Svelte app's `tsconfig.json` now extends `@skathi-native/runtime/tsconfig.svelte.json`, which types the runtime without Vue. Change its `extends` from `@skathi-native/runtime/tsconfig.app.json` to that.

</Change>
<Change title="Compiled effects are schema 11" who="Apps with effects">

`corner-shape` grew the data each effect draws with, so the effect schema went from 10 to 11 and the built-in effects were regenerated. A 0.4 host refuses an `effects.json` built for 0.3, with `effects.json is schema 10 but this build understands 11`. Rebuild the app, or an embedder's payload, with `sk` 0.4.

</Change>

## Known limits

<Aside kind="warning" title="What 0.4 does not do yet">

- **Spatial audio is Windows-only.** Elsewhere, and without a spatial sound format, `"spatial"` panners render with HRTF.
- **Only gain follows a spatial panner.** An audio object leaves the graph at its panner. `GainNode`s between the panner and the destination still scale it, but filters, analysers and stream destinations after it do not hear it. Put effects before the panner.
- **No HDR on Linux.** Linux windows stay SDR, `<sk-surface>` takes CPU frames there, and the display reports nothing yet.
- **`"monitor": "cursor"` is read on Windows only.** macOS and Linux open on the primary monitor, with an advisory. Under Wayland the compositor places the window.
- **`corner-shape` is partial.** The `corner` and `corner-*-style` shorthands are not supported, as in browsers.

</Aside>

## Fixes worth a line

- Scroll snap positions, `scrollIntoView()`, `clientWidth` and `clientHeight` measure from the padding box, as in browsers. A box with a border no longer snaps off by its width.
- A `calc-size()` flex item applies its calculation once: `calc-size(auto, size * 0.4)` over 100px is 40px, not 16 to 20.
- Gradient stops at a `calc()` of a percentage and a length, such as `calc(100% - 200px)`, keep their place, in `background-image` and `mask-image`.
- A declared underline or line-through paints without a declared thickness.
- A Lottie or sticker referenced by URL, through an import, `<lottie src>` or `new URL(…, import.meta.url)`, is packed into the payload.
- `cloneNode()` keeps scoped-style ids, so a scoped `.list-move` class plays.
- WebGPU: `destroy()` of an unmapped buffer works, and native errors are readable.
- `calc-size()` interpolates with `auto` without `interpolate-size: allow-keywords`, as the spec says.
- An error thrown in an event listener is reported as uncaught, and Vue handlers reach the app's `errorHandler`.
- Media that plays or loads keeps the frame clock going in an otherwise idle app.
- On macOS, a window whose `CAMetalDisplayLink` stops delivering frames, as on hosted virtual machines, takes its frames from `CVDisplayLink` instead.
- The "no frames" notice is logged only for a hidden page, not for an idle visible window.
- `<sk-surface>` events are typed in Svelte apps without the app's globals.
- `sk` refuses a Bun older than the app's `engines.bun` and names the binary to upgrade.
- For embedders: an event emitted just before a reload no longer reaches the new page, and a function returning `()` is typed `void`.

## Start from a template

The templates moved with the release. `bun create skathi` offers the showcase, a minimal Vue app, a Svelte app, a music player and a weather app, and each now depends on its framework itself.

- **Showcase.** A new Layout page with container queries, sticky headers, a snapping carousel, `order` and `flex-flow`, and `aspect-ratio`. Styles gains corner shapes, text shadows, colour spaces, `light-dark()`, `@function` and cursors; Forms the native checkboxes and radios; Motion list moves and animating to `height: auto`; Media a focal point with `object-position`; Audio the interactive 7.1.4 spatial room.
- **Player.** Squircle cover art and tiles, and playlist rows that slide into place with FLIP.
- **Weather.** A 24-hour strip that snaps to whole hours, squircle glass, and hero text that stays legible on bright skies.
