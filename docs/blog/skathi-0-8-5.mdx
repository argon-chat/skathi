0.8 was about what you can do with text. 0.8.5 is about how it looks. The same app used to read differently on each system: thin on Windows, too dark on a Mac, and a little taller than the same markup in a browser everywhere. This release takes those apart one by one. Skathi gets a glyph rasterizer of its own, so Windows and Linux draw text the way macOS does; macOS text now matches a native label pixel for pixel; lines are as tall as browsers make them; and text keeps its shape while it moves.

It is also the first release that ends in something to install: `sk package` writes an MSIX, a DMG and an AppImage from one section of sk.config.json.

## Skathi mode

Skathi now has its own glyph rasterizer, and on Windows and Linux it is the default. It draws every glyph the way macOS does: outlines without hinting, a little extra weight that depends on how light the text is, the x-height of small text on whole pixels, and plain linear blending. The result is grayscale and a little heavier than DirectWrite's, light text on a dark ground most of all, which is where Windows text looks thinnest.

How close is it to a Mac? Against CoreText drawing the same text (Manrope 400 and 600, 11 to 24px, 1x and 2x, black, white, grey and coloured, 48 cases), glyph masks differ by 0.25 to 1.1 levels in 255 on average. DirectWrite's differ by 33 to 36. On Linux the rasterizer produces the same masks as on Windows, byte for byte.

The setting is `"textRendering"` in sk.config.json. `"skathi-mode"` is the default on Windows and Linux; `"optimized"` keeps the platform's rasterizer, DirectWrite with ClearType as 0.8 drew it; on macOS both draw with CoreText.

```json
{
  "textRendering": "optimized"
}
```

`SK_TEXT_RENDERING=optimized` in the environment switches it without a rebuild, and `Builder::text_rendering` does it for embedders. The [text rendering guide](/guides/text-rendering/#two-rendering-modes) says when to pick which.

<Aside kind="warning" title="Experimental">

Skathi mode is the default so that it gets tried on real apps and real displays. Its output may still change between releases, and `"optimized"` is the stable choice. In this mode `font-smoothing: subpixel-antialiased` and `font-dilation` do nothing, text in many colours takes more room in the glyph atlas, and a glyph takes 2 to 5 µs to rasterize the first time it is drawn, up to 4.6 times as long as before. Emoji are drawn as before.

</Aside>

### `font-smoothing` and `font-dilation`

For `"optimized"` mode there are two new inherited properties. `font-smoothing` picks grayscale or subpixel text: `auto`, `antialiased` or `subpixel-antialiased`. `-webkit-font-smoothing` is read as the same property, and `sk check` suggests the unprefixed spelling. A Skathi window has a Mica backdrop by default, and Windows draws ClearType only over an opaque one, so under `auto` the text of a default window is grayscale; `subpixel-antialiased` asks for ClearType anyway, and is right only where the text sits on an opaque panel.

`font-dilation: luminance` gives text more weight the lighter it is, as macOS does: light text at 14px gains 6 to 15% ink and dark text is unchanged, so a dark theme stops reading thinner than its light twin.

### Glyph positions by size

On Windows and Linux a glyph is placed in steps that depend on its size: quarters of a pixel below 12px, thirds up to 16px, halves from 17px and whole pixels from 34px, where it was quarters at every size. Small text keeps its spacing, and the glyph atlas holds 7 to 23% fewer tiles.

## macOS text as native apps draw it

Text on macOS was darkened twice. CoreGraphics thickens each glyph by an amount its colour selects, and Skathi's Metal renderer then applied the gamma and contrast correction that DirectWrite text needs on Windows. Coverage is now blended as it is, the way macOS composites a label.

The rest follows the system too. The thickening is chosen from the colour's linear luminance, so light grey, green and red text get the weight they get in a native app (red used to get black's). Glyphs sit in the steps macOS uses for their size. `font-weight: 500` on the system font selects its Medium design, which was drawn as Regular before. Against CoreText drawing the same line in the same colour, every pixel now matches: at 13 and 24px, on 1x and Retina displays, for black, white, greys and saturated colours.

One thing to know: `font-smoothing: antialiased` now does on macOS what it does in Safari and turns the thickening off. Tailwind's `antialiased` class sets it, so an app that uses that class draws thinner text on macOS than before, as the same page does in Safari.

## Lines as tall as in a browser

Text whose line height no rule declared used to get 1.618 of its font size, about 0.4 em more than a browser gives it. It is now CSS's `normal`, taken from the font's own ascent, descent and line gap and rounded as Chromium rounds them: Segoe UI at 16px is 21px tall and Arial 18px. An interface that never declares `line-height`, as most written for the web don't, comes out at the heights it has in a browser.

### The box of a native label

Two new inherited properties build a line the way AppKit and SwiftUI build a label's. `line-metrics: snapped` rounds the font's ascent and descent to whole pixels and leaves out the line gap, so the baseline falls on a whole pixel. `line-leading: above` puts all the leading above the font's box instead of half above and half below. Together, 13px text is 16px tall with its baseline at 13, and a 24px button that centres it puts the baseline at 17: where macOS puts it.

```css
html {
  line-metrics: snapped;
  line-leading: above;
}
```

The new [text rendering guide](/guides/text-rendering/) puts these together into a preset for the root of an app, and the apps `sk create` makes start with it.

## Text in motion

Three things used to give moving text away.

Under a moving `translate()` each glyph was placed on its own, so the gaps between letters changed by up to half a pixel from frame to frame and words seemed to shimmer. The translation is now rounded once for the whole text, and letters and lines keep their distances.

Under a `scale()` text was drawn from glyphs rasterized at the original size and stretched, so `scale(1.14)` came out soft and stayed soft. Once a transform has been still for 200 ms, the text under it is now rasterized again at the size it is shown at. A transform that keeps changing stays resampled, and nothing keeps running once the text has settled.

And text stepped by whole pixels against the borders of a box that glided. Inside an element with `will-change: transform` the text now moves with the box as one layer, and plain rectangles, backgrounds and rules are antialiased off the pixel grid, so the box and its text travel together. Letters under a running `scale()` wobbled against each other by up to 0.9 px; they now stay under 0.2. ([#108](https://github.com/argon-chat/skathi/issues/108))

## Fonts and fallback

Each character is now drawn with the first family of the `font-family` list that has a glyph for it, on every platform. On macOS and Linux only the first family was used before. An `@font-face` family after an installed one is reached, a face is used only for the characters its `unicode-range` covers, and a character no font has is the first family's missing glyph everywhere. The [guide](/guides/text-rendering/#characters-the-font-lacks) has the order.

A line with glyphs from another font, such as Chinese text in a Latin font, grows where that font's box is taller, as in Chromium: Manrope at 16px is 22px tall, and 23px with a glyph from a font whose line gap reaches further down. A declared `line-height` never grows.

`font-size-adjust` evens out the sizes: `from-font` draws every fallback font at the size that matches the first font's x-height, and a number sizes the first font too. `cap-height`, `ch-width` and `ic-width` match by another metric. ([#106](https://github.com/argon-chat/skathi/issues/106))

## Packaging

`sk package` turns a release build into what people install. It runs `sk publish`, then writes the formats the new `"package"` section lists for the system it runs on into `dist/package`.

```json
{
  "id": "com.example.notes",
  "protocols": ["notes"],
  "package": {
    "publisher": "Example Ltd",
    "icon": "icon.png",
    "fileAssociations": [{ "extensions": ["note"], "name": "Notes document" }]
  }
}
```

Most of the section defaults from keys the app already has. `--from <dir>` packages a folder built another way, such as a Rust program that embeds Skathi, and `sk check` reports a mistake in the section before anything is built. The [packaging guide](/guides/packaging/) walks through it.

- **Windows: MSIX**, written without the Windows SDK: the manifest with the app's file types and URL schemes, tile and taskbar images at every scale with the `resources.pri` Windows picks among them with, the block map, and an `.appinstaller` feed for updates. `sk package` prints the publisher the signing certificate must carry; signing is still a `signtool` step of your own.
- **macOS: DMG** with the signed app, a link to Applications and a Finder window laid out from the config. The layout is written as Finder's own `.DS_Store`, so it builds headless on a CI runner. With `"notarize"` the app and the image go to Apple's notary service and get their tickets stapled.
- **Linux: AppImage**, written on any system, Windows and macOS included. `sk package` builds the squashfs itself, so neither `mksquashfs` nor `appimagetool` is needed. It holds a desktop entry, icons and AppStream metainfo, and can embed update information and a GnuPG signature. It needs glibc 2.35 or newer.

An installed app behaves like one. Inside an MSIX, `appPermissions` and `navigator.permissions` read the app's own switch in Windows' privacy settings, where a packaged app is listed by name, and a request shows Windows' own question in place of the app's dialog. A launch with a URL of a scheme the app declares arrives as `appLaunch.url` on every platform.

## Fixes worth knowing

- `text-box-trim` trimmed the font's descent too much, so a trimmed box was shorter than its glyphs. It now leaves exactly the edges `text-box-edge` names.
- A `transform-origin` from a class now applies to a `transform` set in a `style` attribute or by `@keyframes`; before, it was replaced by `50% 50%`.
- White space between block-level flex boxes no longer takes a line of its own. ([#101](https://github.com/argon-chat/skathi/issues/101))
- Windows: while a window is moved with `appWindow.startDragging()`, the page keeps running (timers, animations, video) instead of freezing until the button is released. ([#110](https://github.com/argon-chat/skathi/issues/110))
- macOS and Linux: an `@font-face` family whose declared name differs from the name inside the font file is now used.
- Linux: text that no installed font covers, such as Chinese on a system without CJK fonts, no longer holds up a frame for seconds.
- Devtools: a reply with non-ASCII text that arrives split across two chunks is decoded whole.

<Aside kind="warning" title="What 0.8.5 does not do yet">

- **Skathi mode** has not been looked at on a Linux display or with variable fonts, and simulated bold and oblique faces take their outlines from DirectWrite.
- **Packaging.** DMG notarization and the look of the Finder window are untested on a real release, the arm64 AppImage has not been run, and `sk package` does not sign an MSIX itself. [#111](https://github.com/argon-chat/skathi/issues/111) tracks signing through Azure.
- **Fallback fonts** do not grow the line in `<input>`, `<textarea>` and `<sk-editor>`.

</Aside>

## Upgrading

Run the commands at the top of this post and `bunx sk check`.

- Text with no declared `line-height` is `normal` and no longer 1.618 of the font size. To keep the old look, declare it once: `html { line-height: 1.618 }`.
- `line-height: normal` follows the font and is no longer a fixed 1.2. It inherits as the keyword, and each element resolves it for its own font and size.
- Text on Windows and Linux is grayscale and a little heavier. `"textRendering": "optimized"` keeps DirectWrite with ClearType.
- A space at the start or end of a flex or grid item's text is removed, as in browsers: a label written on its own line after an icon no longer makes the button a space wider. Text inside an inline `<span>` beside other text keeps its spaces.
- On macOS, `font-smoothing: antialiased` (Tailwind's `antialiased`) makes text thinner, as in Safari.
- For embedders: build the host and the payload from the same release.
