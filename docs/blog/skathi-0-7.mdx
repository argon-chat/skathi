Skathi 0.7 is about what an app can reach without leaving JavaScript. Ahead-of-time compilation, a Windows feature until now, runs on Apple Silicon and inside an embedder's own executable. The host gets a standard library: thirteen `skathi:` modules for the things every desktop app writes again, from the operating system's name to a diff of two texts. One of them, `skathi:ffi`, calls C functions of a library the app ships, behind a list of permissions. And effects learn to step down when the machine is hot or on battery.

## AOT on Apple Silicon

`sk publish --aot` now works on a Mac with Apple Silicon. The result is one `.app`: the host in `Contents/MacOS`, the payload in `Contents/Resources`, and the image as `app.image.dylib` in `Contents/Frameworks`. `sk publish` signs the image before it signs the bundle, ad hoc by default and with the hardened runtime when you pass a `Developer ID Application` identity.

`"publishJit": false` publishes on the no-JIT workload there too. On a GitHub-hosted M1 runner, the showcase app measured:

| Showcase, macOS arm64 | Warm start | RSS at 5 s | Bundle    |
| --------------------- | ---------- | ---------- | --------- |
| JIT                   | 483.5 ms   | 129.5 MiB  | 96.3 MiB  |
| AOT                   | 358.5 ms   | 120.5 MiB  | 100.9 MiB |
| AOT without JIT       | 291.2 ms   | 119.4 MiB  | 82.7 MiB  |

The first launch after an install is slower under AOT (895 to 1145 ms against 691 ms), and scrolling paces the same in all three. The [AOT guide](/guides/aot/#macos-arm64-measurements) has the method and the raw samples.

## AOT in your own executable

A program that embeds Skathi can run native images as well. The `skathi` crate re-exports `native-aot`, `no-jit`, `no-wasm` and `native-inspector`, and `sk publish --aot --payload-only --workload <your exe>` compiles the payload against it. The [shipping guide](/embedding/shipping/#aot-for-your-own-executable) walks through the toolchain.

An embedder who ported a video player [measured it](https://github.com/argon-chat/skathi/issues/37) on an M3 Max: the idle interface settles 18 MiB lower without the JIT, and its pointer handlers answer about twice as fast as under the JIT.

Devtools no longer need the JIT either. With `"publishJit": false` and `"publishDevtools": true`, the `aot-nojit-devtools` workload ships the inspector as its own image, `inspector.image.dll`, beside the app's.

## The skathi modules

Every host now provides a library under the `skathi:` prefix. There is nothing to install: the modules are part of the host, typed from the runtime package, and work the same under `sk dev` and in a built app.

```ts
import { app } from "skathi:app";
import { os } from "skathi:os";
import { Stopwatch, RetryPolicy } from "skathi:time";
import { TextDiff } from "skathi:text";

console.log(`${app.getVersion()} on ${os.platform} ${os.release}`);

const watch = Stopwatch.startNew();
const saved = await new RetryPolicy({ attempts: 3 }).run(() => upload(file));
console.log(`uploaded in ${watch.elapsed}`);

const patch = TextDiff.unified(before, after);
```

| Module               | What is in it                                                                         |
| -------------------- | ------------------------------------------------------------------------------------- |
| `skathi:app`         | Quit, restart, the app's version; the `app*` objects under one import                 |
| `skathi:runtime`     | The Skathi version, its features, `Runtime.isAot()`                                   |
| `skathi:os`          | Platform, architecture, OS release, host name, home and temp folders                  |
| `skathi:network`     | Online, internet reachability, connection type, metered and roaming                   |
| `skathi:numeric`     | Fixed-width integers and floats: `i8` to `u64`, `f16`, `f32`                          |
| `skathi:toml`        | `TOML.parse()` and `TOML.stringify()`                                                 |
| `skathi:binary`      | Byte and bit readers and writers, byte order, LEB128, CRC-32 and CRC-64               |
| `skathi:encoding`    | Hex, Base32, Base64, legacy text encodings, MIME types                                |
| `skathi:ffi`         | C functions of the libraries the config allows                                        |
| `skathi:text`        | `StringBuilder`, `StringReader`, `TextDiff`, `TextSearch`, `Glob`                     |
| `skathi:time`        | `TimeSpan`, `Stopwatch`, `Deadline`, `Backoff`, `RetryPolicy`, `RateLimiter`, `Timer` |
| `skathi:units`       | `DataSize`, `Frequency`, `Angle`                                                      |
| `skathi:collections` | `BitSet`, `BloomFilter`, `RingBuffer`, `DisjointSet`, `Trie`, `IntervalTree`          |

The classes are native: their contents live in the host, and the methods that take a whole array (`appendAll`, `readLines`, `findAll`, `filter`) cross into it once. Each export has a page in the [standard library reference](/std/). The `app*` objects are still exported from `@skathi-native/runtime`, now marked deprecated.

## C libraries from JS

`skathi:ffi` calls a library you already have as a binary, without a Rust build.

```json title="sk.config.json"
{
  "permissions": {
    "ffi": [{ "name": "sqlite3", "path": "$APP/lib/sqlite3" }]
  }
}
```

```ts
import { dlopen } from "skathi:ffi";

const sqlite = dlopen("sqlite3", {
  sqlite3_libversion: { returns: "cstring" },
  sqlite3_open: { args: ["cstring", "buffer"], returns: "i32" },
});
sqlite.symbols.sqlite3_libversion(); // "3.46.0"
```

- **Permissions.** A library loads only by a name the config lists, from the app's own folder (`$APP`) or from the system's (`$SYSTEM`). `sk build` copies `$APP` libraries beside the exe, and into `Contents/Frameworks` of a macOS bundle. `sk check` compares every `dlopen()` with the list before the app runs (the new `SK6` codes).
- **Types from the signature.** TypeScript types each function from the literal you pass. A value of the wrong type is a `TypeError` that names the function and the argument; nothing is converted silently.
- **Callbacks.** `new NativeCallback(fn, signature)` gives the library a function pointer. The thunks are built into the host, so callbacks work without a JIT.
- **Off the JS thread.** `nonblocking: true` runs a call on a worker thread and returns a promise.
- **Cost.** A call with numbers, pointers or buffers takes 0.1 to 0.2 µs and allocates nothing.

A fault in the library ends the app, after a `[crash] ffi: library!symbol` line that says where. For native code you write yourself, a [native module](/embedding/native-modules/) is still the better path.

## Effects that follow the machine

CPU pressure and the system's power profile reach CSS, JavaScript and shaders.

```css
@media (currently-power-scheme: saving), (currently-compute-pressure: serious) {
  .glass {
    backdrop-filter: none;
    --shading: none;
    background-color: #262634;
  }
}
```

`PressureObserver` reports the same states to script. A shader can declare a `[SkQuality] float` slot and draw three levels of detail; the host picks one from pressure, power mode and battery, and slows the effect's clock to 30 or 15 Hz on the lower two. `effect-quality` pins a tier for one element. The [adaptive effects guide](/guides/adaptive-effects/) has the table per platform.

## Web Audio

The audio graph gets the nodes a synthesizer or an effects chain needs: `DelayNode`, `WaveShaperNode`, `DynamicsCompressorNode`, `ConvolverNode`, `IIRFilterNode`, `ConstantSourceNode` and `PeriodicWave`. `OfflineAudioContext` renders a graph into an `AudioBuffer` faster than it plays.

```ts
const delay = context.createDelay(1);
const feedback = context.createGain();
delay.delayTime.value = 0.375;
feedback.gain.value = 0.4;
source.connect(delay).connect(feedback).connect(delay);
delay.connect(context.destination);
```

- Every node and `AudioBuffer` has its constructor, `new GainNode(context, { gain: 0.5 })`, and a `context` property, which libraries written for browsers rely on.
- Contexts and nodes are `EventTarget`s: `statechange` on a context, `ended` on a source, `complete` on an offline context.
- A feedback loop works with a `DelayNode` in it, as in the spec.
- A `ConvolverNode` takes mono, stereo and four-channel impulse responses and adds no latency.
- `suspend()` now stops `currentTime` as well as the output, and `resume()` goes on from the same time.
- A window that is minimized or covered keeps its timers while an `AudioContext` plays, so a scheduler that looks a few tens of milliseconds ahead keeps time.

The [Web Audio page](/web-platform/web-audio/) lists what differs from a browser.

## Two new templates

`sk create` has two more finished apps to start from. Each one is there to be read as much as to be run: a few hundred lines that put one part of Skathi to real work.

```sh
bun create skathi my-app --template sequencer
```

### `sequencer`: a drum machine

A Svelte 5 app with six tracks, sixteen steps and four patterns. A step is off, on or accented, and each track has a length of its own, so tracks of different lengths drift against each other.

What it shows:

- **Timing on the audio clock.** No note is started by a timer. A timer wakes every 25 ms, looks 120 ms ahead and hands each step in that window to `start(time)`, which is exact however late the timer ran. It keeps playing with the window minimized.
- **A whole mix from Web Audio nodes.** Every drum is synthesized from oscillators, filters and noise; there are no samples. The mix goes through a wave shaper for drive, a delay with feedback for the echo, a convolver with a generated impulse for the room, and a compressor. An analyser feeds the meter sixteen bands a frame.
- **A panel drawn by shaders.** The dials, the keys, the plate and the meter are four shaders of the app's own. Each has three levels of detail, and the host picks one from CPU pressure, the power mode and the battery; a button pins a level so you can see the difference.
- **The `skathi:` modules in small doses.** Patterns are saved as TOML with `skathi:toml`, a line of `.`, `x` and `X` for each track, and the tempo arithmetic is `skathi:units`.

### `rv32`: a RISC-V computer that runs Doom

A Vue app around an emulator of a 32-bit RISC-V machine (RV32IM) with 16 MB of memory. Its guest is the Doom engine, compiled to a 409 KB image for a machine with no operating system. The game draws into a 320 by 200 canvas, and the workbench beside it shows the registers and the next instructions, pauses, and steps by one instruction or one frame.

What it shows:

- **Heavy computation in the app's own JavaScript.** The interpreter decodes each instruction once and keeps the result, and in the clip above it runs 550 to 730 million guest instructions a second under the JIT. A button plays the engine's recorded demo as fast as it goes and reports frames and instructions per second, which makes it a benchmark for the JIT against a native image.
- **A small, complete machine.** Everything the guest needs from outside is one of ten host calls: the screen, the clock, keys, the game file. The guest's side of them, a small C library and the build script are in `guest/`; it builds with `zig cc`.
- **A shader over live content.** The picture tube is a shader that reads the canvas under it and adds the bulge, the scanlines and the vignette, again with three levels of detail.
- **Data fetched at install.** The game data is not in the template. `bun install` fetches the shareware episode of Doom 1.9 and checks its hash, and with `freedoom1.wad` in `assets/` the workbench runs Freedoom instead, as it does in the clip. The engine is GPL-2.0 and the shareware episode may not be sold, so `guest/README.md` says what that means for an app you ship.

The machine has no sound yet.

## Memory

- **Images commit less.** An application image now runs with a compact memory profile: on Windows that is 367 to 378 MB less committed than the engine's own sizes, in pages the app never touched. `SK_AOT_MEMORY_PROFILE=default` restores them.
- **`"memory": "low"`** in sk.config.json trades allocation speed for memory. In the showcase on Windows, private bytes went from 256 to 160 MB, with allocation bursts about 1.3 times slower. The new [memory guide](/guides/memory/) shows where an app's memory goes and how to measure it.
- **GPU copies.** A surface keeps at most two copy slots in steady use and releases them after `clear()`.

## CSS

- `@starting-style` and `transition-behavior: allow-discrete`: an element animates in when it first renders and out when it goes to `display: none`.
- `sibling-index()` and `sibling-count()` for staggered delays without inline styles.
- `field-sizing: content` for inputs, textareas and closed selects that grow with their text.
- `text-box-trim` and `text-box-edge` to trim the space above and below text by font metrics.
- `translate` and `rotate` as properties of their own, and `content-visibility`.
- `image-rendering: pixelated` on a `<canvas>` scales it by nearest neighbour.
- `top`, `left` and the other insets move only a positioned box, as in a browser. A rule that relied on them without `position` needs one.
- `inherit` on a property that does not inherit is reported by `sk check` instead of being dropped silently.

## Fixes worth knowing

- **Vue.** `v-model` updates before an `@input` or `@change` handler on the same element runs, so the handler reads the new value.
- **A failed entry module** in a packaged app opens a dialog with the error instead of an empty window.
- **macOS.** `sk build --payload-only` signs the image containers it writes.
- **`DataSize.format()`** prints bytes as `154 B`.

## Vite+ and tests

- **Vite+.** `sk create` now writes a `vite.config.ts`, and packaged builds go through the Vite+ the app declares, with its plugins. An existing project with a Vite config beside `sk.config.json` gets the same.
- **`@skathi-native/test`** is on npm. The harness that drives a real host in Skathi's own end-to-end tests installs into your app and runs under `bun test`. See the [testing guide](/guides/testing/).
- **`sk check`** also reports a `console` method replaced under AOT, and a built-in written through a key that is one of a few literals.

## macOS

- The host installs the standard menu bar: Quit, Hide, Close Window, Enter Full Screen, Minimize and Zoom, with their shortcuts.
- A custom title bar no longer draws Windows caption buttons beside the traffic lights.
- The camera and the microphone work under `sk dev`.
- Colours outside the display's gamut survive on HDR surfaces.

<Aside kind="warning" title="What 0.7 does not do yet">

- **AOT** is for Windows x64 and macOS arm64. Linux hosts run the JIT.
- **`skathi:text`** has no collation, word boundaries or Unicode properties yet: use `Intl.Collator`, `Intl.Segmenter` and `normalize()`.
- **`skathi:ffi`** passes no struct by value.
- **`skathi:network`** has no `roaming` or `overDataLimit` on macOS and Linux, and no connectivity check on macOS. On Linux, `internet` and `metered` need NetworkManager.

</Aside>

## Upgrading

Run the commands at the top of this post and `bunx sk check`. Under AOT, a logger that replaces `console.error` now stops the build instead of the app: wrap it in `if (!Runtime.isAot())`. Imports of the `app*` objects from `@skathi-native/runtime` keep working and show a deprecation hint that names `skathi:app`. For embedders: rebuild the payload with `sk` 0.7, and a build without the `audio` feature needs the release, not an earlier commit of master.
