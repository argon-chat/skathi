# vn-test fixtures

Apps that exist for a spec rather than for a demo. `apps/` is the shelf of
things worth looking at; this is the shelf of things worth *asserting*, and the
two get in each other's way when they share a directory — an app here may be
eight lines and have a deliberately broken configuration.

`launch({ app: "packages/vn-test/fixtures/<name>/src/main.ts" })` — `resolveEntry`
takes a path as readily as a name (docs/TESTING.md §2).

| fixture | what it is for |
|---|---|
| `measure-on-mount` | the m22 "a DOM layout read lays out" fix (`specs/measure.spec.ts`). `apps/meet-probe`'s join card in twelve lines: measure a child from `onMounted` + `nextTick` and write the answer back as the parent's `height`, with an `overflow: hidden` beside it. It reports what `scrollHeight` answered at every stage a real app measures from — `onMounted`, `nextTick`, the first rAF, `setTimeout(0)`, and one late enough that a frame has certainly been painted — so the spec can pin all five at the browser's number rather than at 0. |
| `measure-late-mount` | the m26 client sweep #8 fix (`specs/measure.spec.ts`, docs/RUNTIME.md §5.8): the same read in a LATER wave. Six lists, each mounted from one wave an app mounts from (a `setTimeout` at 300 ms, a `fetch` completion through `__VN_TEST_LATE__.fetchMount(url)` against the spec's loopback server, a devtools click on `#mount-click`, a real click on `#mount-realclick`, a real press on `#mount-down` and a key on `#mount-key`, the last two from under gpui's listener). Each measures itself in `onMounted`, as the Argon chat list does, and sizes `#bubble-<stage>` at 60% of the width it read; `#seen-<stage>` reports `offsetWidth,rect height,scrollHeight`. |
| `event-order` | one platform event, two JS events, and the microtask checkpoint between them (`specs/event-order.spec.ts`, m26 client sweep #8, docs/RUNTIME.md §5.8). Every handler logs its event, then `<event>:mt` from a microtask, into `__VN_TEST_ORDER__.log`. `#h1` / `#h2` (leave, enter), `#f1` / `#f2` (blur, focus), `#pad` (keydown, keyup, a cancelled `contextmenu`), `#ta` (keydown, a cancelled `copy`), `#btn` (keyboard click, keyup), `#scroller` (scroll, wheel), and a `document` `copy` listener added before `mount()`. |
| `composer` | a chat composer's keys and presses against the default action (`specs/composer.spec.ts`, m26 client sweep #8, docs/RUNTIME.md §5.8). `#composer` is a controlled `<textarea>` whose keydown handler `__VN_TEST_COMPOSER__.reset(mode)` picks: `send` (Enter cancelled, sent, cleared), `clear` (Enter clears and is not cancelled), `upper` (`x` uppercases the value and is not cancelled). `#keep` (focusable) and `#keep-plain` cancel their `mousedown`; `#victim` hides itself from a microtask of its own `mousedown`; `state.focusLog` records focus and blur on `#other` and `#victim`. |
| `popover-click` | the Argon member-click crash (`specs/popover-click.spec.ts`, docs/RUNTIME.md §5.8). `#member` is a `<button>` trigger, as reka's PopoverTrigger renders, so a real press focuses it. Its click toggles `#content`, whose `onMounted` does what reka's FocusScope and floating-ui do: focus the content, then measure the trigger and the content and place one under the other. The reads force a layout whose draw reports the trigger's pending focus, so that `focus` is dispatched from inside the running script. `__VN_TEST_POPOVER__` holds `opened`, `measured` (both rects per mount), `focusLog` and `active`. |
| `devtools-on` / `devtools-off` | the m22 devtools switch (docs/DEVTOOLS.md). Twins: identical code, and their `vn.config.json` differs by one key. `devtools-off` declares the top-level `"devtools": false`, which is the static spelling of `appDevtools.disable()`. Both publish `appDevtools` as a global, because `eval` on the devtools wire runs in GLOBAL scope and a module export is not a global in either boot mode. |
| `shell` | links, `window.open` and `appShell` (`specs/shell.spec.ts`, docs/SHELL.md). One link per shape the tier-1 path distinguishes — https with a listening child (one press must be one click and one navigation), mailto, a custom scheme and `file:` (refused), a cancelled one — and `__VN_TEST_SHELL__.run(verb, …)`, which records how each `appShell` promise settled, because a promise does not survive the eval round trip. Run under `VN_SHELL=record`, so nothing reaches the OS. |
| `launch` | single instance and forwarded launches (`specs/launch.spec.ts`, docs/LAUNCH.md). `"singleInstance": true`; records its own launch (`appLaunch` fields, the first `LaunchParams`) and every forwarded one (the `launch` event, the `LaunchParams` after it) into `__VN_TEST_LAUNCH__` for the spec to read back. The spec starts the "second launches" by hand on the same slot. `specs/launch-packaged.spec.ts` packages the same `src/` with `vn build` under a vn.config.json it writes per run (a `protocols` entry of `vntest-pkg-<pid>`), so the scheme is test-only and never collides. |
| `indexeddb` | IndexedDB in a real Vue app (`specs/indexeddb.spec.ts`, m25 P1). A notes list whose state lives in the database: opened at boot, a click writes in a transaction made from its handler, Vue renders what is read back. `__VN_TEST_IDB__.run(name)` starts a scenario — `surface`, `chain` (500 sequential awaited gets, frames counted on the host's rAF clock), `versionchange`, `constraint`, `structured`, `storage` — and records how it settled into `results`. The databases are on disk since m25 P2, so the spec gives the host its own `VN_APP_NAME` — a fresh, empty storage folder per run, removed afterwards. |
| `idb-persist` | IndexedDB ON DISK across real restarts (`specs/indexeddb-disk.spec.ts`, m25 P2). One key/value store. The launch's own argv picks the encryption BEFORE the first `indexedDB` use (`encrypt` / `decrypt` → `appStorage.setStorageFolder(appStorage.folder, { encrypted })`; `keep` → the same call with no options, which must change no format; none → the sticky rule decides). A failed boot open is rendered (`#status` = `failed: <name>`) for the second-instance test. `__VN_TEST_IDB__.run(name, ...args)`: `put`, `get`, `open`, `databases`, `estimate`, `info` (`appStorage.info().indexedDB`), `late true|false|keep` (a `setStorageFolder` after IndexedDB started). The spec packages the same app with `vn build` for the packaged-exe case. |
| `blob-url` | `<img src="blob:…">` on the real host (`specs/blob-url.spec.ts`, m25 desktop track B, docs/DESKTOP.md §1). Three `<img>`s over one red 8×8 PNG held in memory: `#live` (a URL that stays alive), `#revoked` (revoked before the `<img>` sees it: a broken image and one advisory), `#sliced` (a slice of a larger Blob, so the URL names a window of its bytes). `__VN_TEST_BLOB__` publishes the URLs and how a `fetch()` of the live one settled. |
| `files` | the file APIs on the real host (`specs/files.spec.ts`, m25 desktop track C, docs/DESKTOP.md "Pickers and files"). `#pick` is an `<input type=file multiple accept=".txt,text/plain">` whose `change` reads each File through `FileReader` and `file.text()`. `#label` is a `<label for="pick">`. `#open` calls `showOpenFilePicker`, writes through `createWritable` and asks a `structuredClone` of the handle the same questions. `#dir` calls `showDirectoryPicker` and lists the entries. `#dl` is an `<a download>` on a blob: URL. `__VN_TEST_FILES__` holds `events`, `results` and `run("nogesture")`. vn-test's `VN_DIALOGS=scripted` means every dialog waits for the spec's `app.answerDialog()` / `app.cancelDialog()`, and none reaches the OS. |
| `clipboard` | `copy` / `cut` / `paste` from real keystrokes (`specs/clipboard.spec.ts`, m26 fixes, docs/RUNTIME.md §5.4). An `<input id=field>` (paste cancelled, copy and cut not, Ctrl+X's keydown cancelled) and a focusable `<div id=pad>`, with a `document` paste listener. `__VN_TEST_CLIP__.events` records each event's type, target and store (ClipboardEvent, DataTransfer, writable or not, disabled after). It never writes the system clipboard, so the spec can run while the machine is in use. |
| `events` | `contextmenu`, one event per press and `<img>` `load` / `error` (`specs/events.spec.ts`, m26 fixes, docs/RUNTIME.md §5.6). `#trigger` is a reka-style context-menu trigger (cancels `contextmenu`, opens `#menu`) that also hears `mousedown`/`mouseup`/`click`, with `#inner` inside it hearing the press and release; `#plain` leaves its `contextmenu` uncancelled; `#pad` / `#pad2` take the Menu key and Shift+F10 (`#pad2` cancels the Menu key's keyup); `#key` takes a keyboard click; `#ok` (data: PNG, 8×6), `#bad` (a missing file) and `#blob` (a blob: URL) answer `load` / `error`. `__VN_TEST_EVENTS__.events` records each event with its target, `button`, `buttons`, `detail`, coordinates and `cancelable`. `specs/xhr.spec.ts` borrows it as a plain page to run an `XMLHttpRequest` in. |
| `layout` | the m26 client sweep's layout and paint shapes (`specs/layout.spec.ts`, research/reports/m26/fixes-layout-1.md). `#msgs` is a scroller of chat rows whose timestamp is `hidden` plus a group-hover `display: flex` (the shape that panicked the host when the content moved under a still pointer); `#m-bubble` is MessageItem's bubble around a mention, nested as the client nests it; `#thumb` / `#calc-w` are `calc()` mixing a percentage and a length; `#grid-fill` / `#grid-fit` are `repeat(auto-fill / auto-fit, minmax(100px, 1fr))`; `#bg-px` / `#bg-pct` / `#bg-cover` / `#bg-tile` / `#bg-over` are `background-image: url()` (emojix's two sprite forms, `cover`, `repeat-x`, a gradient above an image), with SVG data URLs for images so the fixture carries no binary; `#bd-glass` is a `backdrop-filter: blur()` panel inside a box moved by `transform: translate()`, over stripes; `#radio` is @argon/ui's checked RadioGroupItem, a 16px `color: lime` button whose 8px lucide dot is positioned absolutely against reka's zero-height indicator span. Render functions and a `.css` import rather than an SFC: this package is `"type": "module"`, and the dev builder's CommonJS interop then hands `main.ts` a `.vue` module's namespace as its default export. |
| `clip` | rounded clipping (`specs/clip.spec.ts`, docs/ARCHITECTURE.md fork items 33 and 34), laid out on white. `#avatar` is reka's AvatarRoot (`rounded-full overflow-hidden`, 64px) around a red `<img>`; `#round-img` is an `<img>` rounded by its own `border-radius: 50%`; `#oval` is `50%` on a 120x44 box around a red fill, which gpui draws as a 22px pill; `#card-a` is a 24px-rounded `overflow: hidden` card around `#list-a`, lime and blue bands that scroll; `#card-b` is a rounded scroller with a 4px gray border, so its rows clip at the inner 20px radius. `#inh-img` is ArgonAvatar's shape, a round wrapper without `overflow: hidden` around an `<img>` with an inline `border-radius: inherit`; `#pcard` is UserProfilePopover's, an 88x46 card whose red background layer rounds itself with `border-radius: inherit; overflow: hidden` and whose blue body takes the bottom corners through two levels of `inherit`. `#perf` is the perf probe's scene: nine rounded cards of scrolling rows with round dots. Render functions and a `.css` import, as in `layout`. |
| `devtools-late` | the Network tee installed AFTER the runtime (`specs/reload.spec.ts`). `"devtools": false` at the top level, and `src/main.ts` calls `appDevtools.enable()` once the runtime has put its realm proxy on `WebSocket` — the order that used to lose WebSocket rows across `location.reload()`. `#late` is the mount. |
| `fonts` | web fonts (`specs/fonts.spec.ts`, m26 client sweep #29, docs/RUNTIME.md §5.15). `src/fonts.css` declares `VN Pixel` (Press Start 2P, a TrueType file that names itself otherwise, behind a `local()` that is skipped) and `VN Tengwar` (Alcarin Tengwar, a WOFF2 variable font with `unicode-range: U+E000-E0FF`), by url()s relative to the sheet, and `VN Late` and `VN Unused` (Press Start 2P again) for lazy loading; both OFL, licences beside them. Probes of "WWWWiiii" at 16px, which Press Start 2P draws 128px wide: `#pixel` (the sheet), `#stack` (behind the PUA-only family), `#inline` (an inline `font-family`), `#script` (a FontFace the `script` scenario adds from an ArrayBuffer), `#plain` (serif) and `#late` (rendered only by the `late` scenario, so its face loads then). An empty `.unused` box names `VN Unused`, which therefore never loads. `__VN_TEST_FONTS__` holds `events` (the set's loading events), `results` (`boot`, `ready`, and each scenario's) and `run(name)` for `script`, `check`, `late` and `missing`. |
| `resample` | images drawn far below their size (`specs/resample.spec.ts`, m26 client sweep #22, docs/RUNTIME.md §5.16), on white. One-pixel black/white checkerboards at 40 x 40: `#img` (a 1080 px `<img>`), `#bg` (the same file as a `background-image`), `#cv` (a 1080 px `<canvas>` drawn once) and `#big` (a 1531 px `<img>`, past the painting thread's budget, so its copy lands from the resampling thread; an odd size, because at a whole or half ratio the atlas samples between texels and hides the aliasing). `#ref` is the 50% grey a filtered downscale gives. The PNGs are generated (a checkerboard compresses to a few KB). Render functions, as in `layout`. |
| `paint-only` | a picture that changes in a box that does not move is a present, not a build (`specs/paint-only.spec.ts`, docs/ARCHITECTURE.md decision 28). `#vid` plays apps/hello's 2 s, 160x90 `clip-tiny.mp4` in a loop, muted; `#cv` is a 64x64 canvas that `__VN_TEST_PAINT__.start(color)` fills with `state.color` on every animation frame until `stop()`, and `state.frames` counts them. Render functions, as in `layout`. |
| `transform-rects` | `getBoundingClientRect()` under CSS transforms (`specs/transform-rects.spec.ts`, docs/RUNTIME.md §5.8, docs/ARCHITECTURE.md fork item 36), laid out on white in 720x520. `#pop` is reka's PopperContent wrapper, `position: fixed` at (0, 0) and moved by `translate()` under `#trigger`; `#menu-btn` inside it opens `#menu`, a second popper anchored to it. `#dialog` is shadcn's DialogContent, centred with `translate(-50%, -50%)`; `#select-trigger` inside it opens `#select`. `Popper` measures its anchor on mount and writes the translate, as floating-ui does for `bottom-start`. `#zoom` runs a 3 s `scale(0.95)` to `scale(1)` open animation on demand under a ResizeObserver; `#far` is translated past the window under an IntersectionObserver, `#near` is not. `__VN_TEST_TRANSFORM__` records each anchor and the observers' entries. Render functions and a `.css` import, as in `layout`. |
| `stacking` | CSS stacking contexts painted atomically (`specs/stacking.spec.ts`, vn-tree `render::Stacking`, docs/ARCHITECTURE.md fork item 37), laid out on white in 720x520. `#popover` is the Argon profile popover's shape: reka's `fixed z-50` wrapper around a 16px-rounded `relative` card whose `#card-bg` (blue, `absolute`, z 0), hero spacer (z 1) and `#glass` (lime, z 2) each make a context. `#menu` is the menu its ⋯ button opens, a LATER `fixed z-50` over the glass zone, with three red items `#item-1..3`. `#neg` is a z-1 context (blue) whose in-flow lime box is overlapped by a `relative` red box at z -1. `#faded` is an `opacity: 0.98` box at z auto holding a red z-100 box, which the later z-10 `#cover` (lime) covers. `__VN_TEST_STACKING__.clicks` records the id of every box whose click listener ran. Render functions and a `.css` import, as in `layout`. |
| `selection` | document text selection by mouse (`specs/selection.spec.ts`, docs/RUNTIME.md §5.17). `#p1` is "Hello " + `<b id=big>big</b>` + " world" (three runs), `#p2` an element with its own text, `#none` a `user-select: none` paragraph, `#p3` another paragraph, `#btn` a button and `#field` an `<input>`; `#scroller` is a 48px scroll box of twelve lines for autoscroll. `document` listeners count `selectionchange` and `selectstart`, and record what each `copy` saw selected, in `__VN_TEST_SEL__`. The copy is not cancelled, so the spec saves and restores the system clipboard around its Ctrl+C. Render functions, as in `layout`. |
| `hit-target` | a mouse event goes to the topmost element under the pointer and bubbles from there (`specs/hit-target.spec.ts`, docs/RUNTIME.md §5.18). `#card` is a sibling painted over the listening `#backdrop`; `#overlay` closes on `click.self` around `#pic`; `#btn` holds `#btn-label`; `#decor` is `pointer-events: none` over the listening `#under`, with `#decor-auto` opting back in; `#outside` is positioned below its listening `#parent`'s box; `#field-cover` lies over `<input id=field>`; `#list-cover` over the top of the scroll box `#list`; `#row` holds `#ra` and `#rb`. `#clist` holds rows a retained-render boundary replays (`#tick` redraws ten times a second), each with `.c-cover` over the listening `.c-under` by a negative margin. `__VN_TEST_HIT__.log` records `<event>:<listener> t=<target id>`, with a `document` mousedown listener logging every target. Render functions, as in `layout`. |
| `keys` | one `keydown` and one `keyup` per key, at the focused element (`specs/keys.spec.ts`, docs/RUNTIME.md §5.19). `#inner` is focusable and listens for nothing, inside the listening `#box` and `#wrap`; `#field` closes itself on Escape (a `#reopen` button takes its place); `#plain` is a field with no listener of its own. `document` listens for both events. `__VN_TEST_KEYS__.log` records `<listener>:<event>:<key> t=<target id>`. Render functions, as in `layout`. |
| `hit-perf` | the prepaint cost of hit targeting (research/reports/m26/hit-target-1.md §3). `VN_SCENARIO=<n>` cards of five elements (default 600, ~3 000 elements) under a counter that changes every animation frame, so the window draws every frame; run under `VN_PERF=1`, with `VN_NO_CACHE=1` for the worst case. |
